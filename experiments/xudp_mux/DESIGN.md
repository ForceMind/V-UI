# Bounded shared-mux write experiment (2026-10-17)

This is a new isolated experiment based on V-UI `160cfdcadeb2e512ef08b7700950f1e06b40d77d`, not a product core, release, or qualified UDP capability. The prior 7/20, 18/20 and 19/20 original gates and their failures remain unchanged. PR 48 remains Draft at its own head. Fixed source is sing-box `af6e64c3b69e6132ebaee0e1a3d24e93903f6709` and sing-vmess `31ec11e8790c48a4bf11711806a61e929ee6b89d` under the fixed sing-box module graph.

## State and ownership contract

- One writer goroutine owns all parent transport writes, including TCP Write/WriteBuffer, UDP Write/WriteTo/WritePacket and StatusEnd. No writer-unwrapping escape hatch remains.
- At most 64 admitted stream identities per parent, including active streams and tombstones awaiting completed End. An entire public TCP write is serialized by a per-stream cancellable gate, including all its chunks. Each has at most one admitted data frame (queued or in flight) and one reserved End. Maximum per-frame payload is 65,535 bytes. Large TCP writes are split into sequential frames with partial-write accounting; oversized UDP datagrams are rejected explicitly. Maximum serialized address is bounded by the existing address serializer; additionally reject any serialized data frame larger than 65,807 bytes. Thus owned queued/in-flight frame bytes are at most 64*(65,807+6)+6=4,212,038 (the extra 6 bytes are one reserved recv-side rejection frame). A single construction scratch frame may exist while holding the admission lock (65,807 extra bytes). The one recv loop additionally owns at most one 65,535-byte incoming payload. It consumes that complete payload before waiting on admission/tombstone/rejection, so sequential write-then-read clients can drain the prior End. Queued external callers retain their caller-owned arguments; the API cannot bound arbitrary caller allocations and does not claim to do so. It creates no goroutine per caller.
- Frame copying occurs only after obtaining the per-stream slot and before publishing the frame. The writer owns those copied bytes until actual write completion or queue withdrawal. Buffers passed to WriteBuffer/WritePacket are released exactly once by that call; a canceled caller cannot free the writer's copy.
- Close first closes the local pipe and all stream waiters. A queued data frame is atomically withdrawn and its caller receives an explicit closed error. An already-started frame is never truncated, including after partial Write; its caller may return closed while the sole parent writer retains responsibility for completing the frame. A canceled write is not safe to blindly retry and is never reported successful.
- Close queues exactly one reserved End behind any already-started data frame. It never waits for transport progress and never sets a parent deadline or closes the parent connection. No data may be admitted after Close. The tombstone is released only after the End Write has actually completed, not after its peer has started reading.
- Remote End closes the stream without generating a redundant End. An already-started outgoing frame still drains; its tombstone remains until completion. Stale stream handles cannot act on a new stream with the same wire ID.
- Unknown Keep and over-capacity New receive an explicit error-End through one fixed additional 6-byte rejection slot, owned by the single recv loop. The complete rejected request payload is consumed/discarded before waiting for End completion. Thus a client that writes its request before reading cannot deadlock on unread request payload. No new stream/worker is admitted and no success is reported. This also avoids a full-active-table deadlock where an earlier over-capacity New would otherwise prevent reading a later End that frees a slot.
- Same-ID New waits on a closing tombstone, avoiding the peer-read/server-return race. Duplicate New for a still-active ID is a protocol fault. Rejection/tombstone waits backpressure the one recv loop and later sibling input while the parent writer is blocked; uninterrupted sibling service is not claimed. When writes resume, explicit rejection and existing sibling traffic must recover with intact framing.
- An indefinitely blocked parent retains one bounded writer and bounded frame/tombstone state; queue-empty, End-delivered, or full-parent reclamation is not claimed in that state. Cancellation linearizes under the state lock: if it wins before actual completion, a later completed wire write cannot change the caller result to success.
- Actual parent cancellation/transport errors close that parent's transport, terminate all stream waiters, discard queued buffers and join the writer and cancellation watcher. This fault path is distinct from association cancellation and is not evidence of sibling isolation.

## Route interaction

The earlier route patch closes only the owned outbound. A second narrow delta, only under its existing explicit UDPConnect + explicit UDPTimeout + newly-created timer guard, also closes that association's timer-wrapped inbound on timeout. The experimental mux Close is nonblocking, so actual route copy workers can exit while one parent writer drains. No other timer guards are broadened.

## Acceptance and stopping conditions

Two new arms use identical tests and fixed dependencies: route-only (frozen address + route patches) and mux (those patches plus these two new deltas). Tests must separately observe the known route-only retained copy workers and the mux arm's zero association copy workers before restoring reads. Parent writer retention is counted separately and never hidden in copy counts.

Cover actual mux reply and End backpressure, prefix/partial-frame write and recovery, queued cancellation, caller-buffer reuse, concurrent TCP/UDP output entrypoints, close/cancel races and exactly-once End, unknown-Keep flood, slot exhaustion, same-ID tombstone reuse, bounded bytes/frames, sibling recovery, and parent cancellation/error joins. Route tests exercise actual ConnectionManager and actual HandleMuxConnection. Old helper/test13 and original gates are not edited. New Go controls are not a substitute for TLS/official-device end-to-end runtime qualification.

Local Python/static checks, compiled Go/race checks and actual transport tests are reported separately. No unrun stage is green. Any failure is retained with exact commit, attempt and logs; unchanged-code reruns cannot erase it. This experiment cannot merge into product, alter pins, upload experimental binaries, release, deploy or contact upstream.
