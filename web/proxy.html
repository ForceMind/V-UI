          04 · 使用与边界

          本机入口仅监听 127.0.0.1。HTTP 使用显式 CONNECT，SOCKS 使用 socks5h 让目标主机名交由代理解析。Git 仅 HTTPS 远端使用显式代理；Git SSH 不在此范围。

          以下只含示例用户名，不含密码。在交互终端中，curl 仅收到用户名时会提示代理密码；非交互脚本不要沿用此写法。勿将真实密码写入命令、环境变量、URL 或 shell 历史。使用你配置的端口；这些命令会访问 ipify，且单次禁用 NO_PROXY 绕过。

          curl --noproxy "" --proxy http://127.0.0.1:7891 --proxy-user example-user 'https://api64.ipify.org?format=json'
curl --noproxy "" --proxy socks5h://127.0.0.1:7891 --proxy-user example-user 'https://api64.ipify.org?format=json'

          Git HTTPS 示例：env -u NO_PROXY -u no_proxy git -c http.proxy=http://example-user@127.0.0.1:7891 ls-remote https://example.com/repository.git。仅对本次命令清除代理绕过项。Git 会按现有凭据机制获取密码，请使用可信提示/助手，并留意助手是否会保存密码。不要把密码追加进代理 URL，也不修改全局 Git 配置。

          参数依据：curl 代理鉴权说明、curl 密码提示实现、Git HTTP 代理说明。命令示例不代表本次线路已验收。

          业务 DNS 固定经所选上游访问 Cloudflare DoH（cloudflare-dns.com / 1.1.1.1）。Cloudflare 会收到业务域名查询；上游为域名时，引导解析可能把上游主机名交给系统 resolver。检查后固定上游 IP，地址变化需明确重新应用。

          拒绝私网、loopback、metadata、保留和自身目标；不提供业务 DNS 直连兜底。此功能不接管全机或设备系统 DNS，也不提供 TUN、透明代理、ICMP/ping 或应用 UDP。普通节点导出继续在原页面使用；URI 本身不保证全系统代理。
