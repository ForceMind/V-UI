# Cloudflare DNS-01 与通配符证书使用指南

本页对应**v0.4.23源码候选，尚未公开或部署**。实现与独审已收口，准确候选的完整Actions、四目标、新装和旧版升级资格仍待完成。公开稳定版与短安装入口仍是v0.4.22；不要把本页当作22已有功能或已验证真实Cloudflare签发的证明。

本流程从**已经安装、能够登录的面板**开始，只由管理员配置。首次安装仍默认HTTP-01，需要满足公网TCP 80与域名条件；DNS-01不自动改造初装流程，也不会关闭其他证书使用的80端口。

## 准备域名与凭据

1. 确认域名实际由你的Cloudflare Zone托管。证书域名可以是该Zone本身或其下的子域名。
2. 在Cloudflare创建仅限目标Zone的API Token，权限选`Zone → DNS → Edit`与`Zone → Zone → Read`，不使用Global API Key。官方权限表将DNS写权限列为`DNS Write`，Token可按资源限制授权，见[创建Token](https://developers.cloudflare.com/fundamentals/api/get-started/create-token/)与[权限说明](https://developers.cloudflare.com/fundamentals/api/reference/permissions/)。
3. 登录面板“证书管理”，展开“Cloudflare凭据（仅管理员）”，填写名称、实际DNS托管域名和Token，选择“验证并保存”。Token只写入、不显示或复制；页面用完会清空。

保存只执行准确Zone的只读核对，**不创建测试TXT，也不证明DNS写权限已经通过**。Token能读取Zone却不能写DNS时，保存可能成功，随后签发会明确失败；请核对授权，不反复提交同一个结果未知的请求。

Token保存在服务器私有凭据目录，旧修订供正在运行的任务与清理使用。替换Token不会把证书换到另一个托管域名或另一份凭据，也不会自动启用已禁用或恢复待确认的凭据。

## 选择证书覆盖范围

在“添加连接域名”选择“通过Cloudflare DNS验证”，填写不带协议、端口、路径或`*`的证书域名，选择凭据与覆盖范围：

| 选择 | 例子中的实际覆盖 |
| --- | --- |
| 仅此域名 | `example.com` |
| 此域名和全部一级子域名 | `example.com`与`*.example.com`，包括`node.example.com`，不包括`a.b.example.com` |

旧HTTP证书、DNS单域证书和DNS根域+通配符证书可以在同根域、同环境下共存，各自有ID；不能把原HTTP记录直接改成DNS身份。邮箱、正式/测试环境与CA条款仍须本人核对，明确同意管理本次签发和续期的验证TXT记录后再申请。

等待“申请/续期结果”和“绑定应用结果”分别完成。测试环境材料不能用于正式节点；失败保留旧材料，不关闭TLS校验，不回退HTTP或换其他账号。

## 设置实际连接域名与节点

例如证书覆盖`example.com`与`*.example.com`，节点实际使用`node.example.com`：

1. 由你在DNS管理中核对`node.example.com`的A/AAAA记录，指向该节点所在服务器；只有确实有可用IPv6时才配置AAAA。V-UI不会修改A/AAAA或替你决定已有记录用途。
2. 对本项目普通VLESS/TCP/TLS预设，连接域名使用Cloudflare的**仅DNS（DNS only，灰云）**。普通橙云代理处理HTTP/HTTPS，不能当作通用原生TCP转发；仅DNS返回源站地址，TXT记录本身始终是仅DNS。具体边界见[代理状态](https://developers.cloudflare.com/dns/proxy-status/)与[代理端口说明](https://developers.cloudflare.com/fundamentals/reference/network-ports/)。本指南不配置额外代理产品，也不代你切换橙云或修改记录。
3. 新建或编辑节点时选择该证书，明确填写“实际连接域名”`node.example.com`。在证书卡片绑定已有节点时也填写此项。它必须是证书覆盖的具体域名，不能把`*.example.com`直接用作SNI。
4. 核对分享给客户端的服务器地址、端口及SNI。面板管理地址、节点连接地址和TLS名称是不同字段，不凭证书签发成功猜测连接地址。

DNS-01证明域名控制，不证明A/AAAA已指向本机、端口已开放或客户端已经连通。保存成功、核心应用和外部连接分别检查。分享链接、二维码及订阅含连接凭据，不要公开发送或上传到不可信转换网站。

仅切换托管证书时，原协议、传输、UUID/密码和未知高级字段继续保留；无法安全表达的配置会拒绝，不靠删字段解锁。续期保存具体SNI，手动停止的核心不会被自动复活。

## 续期、升级与维护授权

管理员可开启自动续期；面板服务停止时不会继续签发。替换Token仅创建该份凭据的新修订，已开始的任务仍固定原修订，不能假定轮换立刻修复正在运行的任务。

已有有效DNS面板绑定通过受支持安装器升级时，会复用已应用的旧revision，不重新签发或修改联系人。同一证书ID尚有待应用版本时，期望值与错误继续保留，当前已应用材料不会被“待应用”覆盖；期望/已应用ID冲突或材料损坏时停止并要求核对，不混用身份。

原维护授权的`certificates`权限不会扩大为DNS写入。维护者可以查看脱敏状态、绑定和使用既有材料；DNS手动签发/续期设置、凭据和遗留记录管理仍仅限管理员。管理员已明确开启的后台自动续期按原设置执行，HTTP维护权限保持原范围。

## 清理遗留验证记录

证书页的“遗留的DNS验证记录”仅管理员可操作：

- **使用当前凭据清理验证记录**：明确确认后排队，由后台只处理原任务自己的TXT ID；不重签、不重建验证记录、不删除同名其他TXT或整个记录组。已禁用的凭据可仅用于清理原任务。
- **未知写入仍待清理**：网络超时或结果不明时，系统保留记录。一次查无结果不代表先前写入已停止，不自动显示清理成功；先读回状态，不盲目重发。
- **我已在Cloudflare确认没有残留**：仅在你已核对原任务无残留时明确确认。服务器还会进行有界只读核对；通过后记录为`manual_confirmed`，这是人工确认，不是自动清理成功，也不会重签。

若凭据处于“恢复后待确认”，先由管理员验证并启用，再清理；不能借清理绕过恢复确认。需要替换已失效Token时，仍使用原来的凭据和托管域名，随后明确选择当前修订进行cleanup-only恢复；原任务身份和历史修订不删除。

## 备份、恢复与版本回退

完整私有备份包含Token、全部保留修订和挑战journal，是**0600权限的ZIP，但没有加密**。请保存在受保护的私有位置；不要上传到公开仓库、Issue、Actions日志或下载目录。

只要含DNS证书、凭据或挑战记录数据，备份采用`backup-dns01-v1`，通用manifest schema仍为1。真实旧v0.4.22 reader会在替换数据前拒绝此kind；受支持activate/restore/在线升级也会在切换前检查DNS读取能力。**含DNS数据不能通过旧运行时回退**，不要手工改kind、删字段或删除数据库绕过。无DNS数据的旧备份格式继续兼容。

新版本恢复先验证完整引用闭包。恢复后所有已保存的Cloudflare凭据禁用并标为待管理员验证，证书原有的自动续期选择保持；原证书/节点材料仍保留，但确认前不会自动写远端DNS。恢复不会让已在Cloudflare撤销的Token重新有效。原管理会话、维护授权及订阅令牌的恢复撤销规则继续适用。
