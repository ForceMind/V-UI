# 服务组 CPU 配额饱和后的恢复

状态：测试草稿，准确候选尚未运行。产品仍与5f逐字相同。本profile只补原卡“过载需可恢复”的一个CPU场景，不代表内存耗尽、连接数耗尽、全部协议、吞吐上限、真实整机或长期稳定资格。

沿用原512MiB、一CPU、零swap及完整29个短控制阶段，在真实安装包sing-box、产品watchdog和面板并存期间插入一个有界阶段。压力全部来自TLS验证开启、明确proxy-only的loopback真实请求；没有人工CPU忙循环、暂停进程、缩小配额或缓存回收。

固定最多8/32/64条请求lane各20秒；保存每条lane的生命周期和实际成功数，不将配置并发数冒充全窗持续活跃连接数，正文为复用的1MiB合成常量，不保存响应体。全批最多65536次尝试/64GiB潜在正文；这是累计loopback流量上限，不是常驻内存。发起前加锁预留整次正文，失败与在途也计预算，并预留48次恢复额度。任何上限到达即停压并留下未完成证据，不事后放大上限追绿。固定预算不保证能观察到饱和。

每档在共同起点0/5/10/15/20秒记录服务cgroup CPU/内存/OOM及角色身份，另记外部发生器/target线程所在helper和client的CPU/RSS。外部采样器不归入服务用量；服务worker、panel、watchdog、server均保留。读取是顺序快照，不是原子峰值分解；相同宿主的调度争用仍存在。

预先固定触发合同：连续三个5秒窗中，服务用量至少0.95核、受限周期数/总周期数至少80%、throttled_usec增长且确有完整正文成功；core自身至少占该窗服务CPU的80%、worker不超过0.1核。角色使用utime+stime和实际SC_CLK_TCK，避免将watchdog子CPU再次相加。上述阈值只用于本夹具保守确认，不是用户性能承诺或内核通用过载定义。throttled_usec不当作wall百分比，也不与usage相加。普通低负载也可能有少量throttle；仅有延迟/超时、发生器GIL瓶颈或吞吐平台均不能单独证明服务饱和。未达到合同就结构化记录not_triggered；夹具和恢复健康时继续执行原29阶段，最后独立拒绝本压力资格，不把未触发改判功能缺陷。

每档停止发起压力请求后立即开始15秒绝对恢复时限，排空/关闭在途也占该时限，最多允许5秒卸载。每秒新单连接请求及真实HTTPS认证面板健康须连续六轮成功；失败保留并在剩余固定窗口内重新计连续次数。原core/watchdog/panel身份不得改变，不能重启服务清队列；全部OOM门槛保留。每轮响应有一秒绝对上限，主动到期shutdown/close连接，覆盖持续滴流；单个socket空闲timeout不能替代这个上限。target进入、target写完与client验满正文分别计数，进入handler不能冒充成功送达。

helper只接受当前临时目录内固定二进制/CA/夹具与准确source/unit/角色。假登录Cookie仅留临时请求文件，不进入保存的JSON或日志。结果包含部分失败、实际字节和请求计数、阶段原始样本、每次恢复及清理证据。finally有界清理helper进程组、client、目标连接及线程；无不受控重试。独立label工作流使用同一既有read-only权限和固定官方依赖，不加入每次普通PR或90分钟回归。

当前仅本地合同与反例通过，真实触发、资源数字及恢复结果必须等待准确新head运行。0aa双核心及其普通8组已经全部首轮通过，但不冒用为本profile证据。512大数据完整流程触限/余量未证明、160MiB工程预算、受限root全流程、真实整机/24小时仍分别待验。
