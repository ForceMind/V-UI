# 节点、代理与订阅配置

本页适用于 v0.4.22。先完成[安装与登录](INSTALLATION.md)，普通任务使用面板的简化入口；需要指定协议和字段时再打开完整高级编辑，并核对[兼容矩阵](COMPATIBILITY.md)。旧节点不会自动转换为推荐配置。

## 创建直连节点

1. 在节点页面选择“创建直连节点”。直连方向为“手机或电脑 → 本机 → 目标网站”。
2. 确认名称、建议端口和适用的正式证书。唯一可用证书会默认选择，多张时选择域名，没有证书时先到证书管理申请。
3. 选择“创建并获取连接”，等待保存和应用结果，再复制链接或显示二维码给客户端。

推荐向导使用 sing-box / VLESS / TCP / TLS / 单用户。建议端口为 10443，简单向导限定 1024–65535；数据库中未被占用不代表操作系统端口空闲或公网已放行。普通 TLS 的 flow 保持空，证书校验开启。

节点地址是客户端连接的域名或 IP，TLS SNI 是证书名称，面板地址是管理入口，三者不能直接互换。CDN 面板地址也不自动获得节点转发能力。

## 创建中转节点

方向为“手机或电脑 → 本机入口 → 另一服务器出口 → 目标网站”。先在出口 V-UI 中创建合资格节点，选择专用的“给中转服务器使用（仅 TCP）”导出；不要把普通设备分享链接手工删字段后冒充上游配置。

在入口 V-UI 选择“创建中转节点”，使用已有出口或粘贴专用 TCP 上游链接，按提示检查并应用，再获取设备连接。更换共用出口时先核对受影响对象。

所有中转节点与服务器程序代理共用**一个选定上游**，不是每个节点有独立出口。上游导入、草稿保存、检查与应用是不同步骤；有效中转失败时关闭受保护流量，不回退直出。未获得资格的入口会被拒绝，不静默转换协议或丢弃配置。

### 每入口路由

高级编辑中的“已保存路由策略”控制入口出口：

| 策略 | 应用后的行为 |
| --- | --- |
| 跟随全局 | 默认入口中转开关关闭时普通直连，开启时经选定上游 |
| 指定直连 | 使用本机普通出口，不随默认中转开关变化 |
| 指定中转 | 经唯一选定上游，不随默认中转开关变化 |

“直连”仍通过此服务器，不代表设备绕过节点。服务器程序代理开关独立于这些策略。显式策略限定合资格的 sing-box / VLESS / TCP / TLS 单用户入口；REALITY 上游资格不自动授予 REALITY 入口显式策略资格，详见[每入口契约](PER_INBOUND_ROUTING_CONTRACT.md)。

有效中转只支持已验证 TCP，应用 UDP 被拒绝；普通直连已有 UDP 能力不因此统一关闭。Xray 普通节点可用能力不等于 Xray 中转能力，保留现有资格拒绝。专用上游格式和凭据规则见[TCP 上游说明](TCP_UPSTREAM_EXPORT.md)与[导出契约](TCP_UPSTREAM_EXPORT_CONTRACT.md)。

## 服务器程序代理

在“服务器程序代理”任务中选择出口，点击“开启并获取使用方法”，按返回说明让服务器上的程序使用代理。监听固定为 `127.0.0.1`，需独立鉴权；保持已有账号和密码，不复用面板管理员凭据。

仅明确使用此代理的程序受影响，不接管整台 Linux 服务器、ICMP、手机或电脑全流量，不提供系统 TUN。HTTP CONNECT 与远端解析的 SOCKS 用法见[详细使用说明](DUAL_PROXY_RELAY_M3.md)；不要把含密码的完整命令贴入公开日志。

## 编辑与实际应用

节点“设置”提供名称、端口、证书和出口等常用项，其他参数使用“完整高级编辑”。普通编辑锁定 core / protocol；迁移协议或核心应新建节点。

- 已有 UUID、密码、REALITY 私钥和 short ID 不回显；对应秘密输入为空时按协议保留原值，新建空凭据由系统生成。非空填写表示明确替换。
- 托管证书绑定会回填。仍使用 TLS 时，解绑需提供不同于原托管材料的证书与私钥路径，不能仅关闭续期却继续引用旧材料。切回 TLS 时须重新选择证书或提供手工材料。
- 不支持或无法表达的高级字段保留或拒绝，不通过编辑静默清除来解锁分享。取消不写入变更。
- 其他页面删除并重建过节点时，旧编辑或删除确认会被拒绝。先保留草稿，刷新后重新打开当前对象；升级后也应重载已打开的页面。

保存成功不等于核心已应用。检查期望配置、已应用出口、核心状态和错误；“已保存但未应用”时，运行中可能仍是旧配置。手动停止核心后，保存或证书续期不会擅自启动它。**删除已保存但应用失败时，旧运行入口可能仍存在**；必要时明确停止受影响核心，再修正并应用。

## 分享与订阅

单节点分享可复制链接或显示二维码；供另一 V-UI 使用时选择专用 TCP 上游导出。分享内容含连接凭据，只交给获授权的人，不粘贴到不可信转换网站。

“订阅分享”选择节点后生成地址，默认使用当前连接地址、90 天和 Clash/Mihomo 格式；按实际需求确认名称、地址、格式、节点范围与有效期。一个订阅内的节点共用填写的连接地址，不同服务器地址应分别创建订阅。

| 输出格式 | 内容 |
| --- | --- |
| Mihomo YAML | 节点、策略组、DNS 与 ToClash 分流规则 |
| URI / Base64 | 节点连接信息，不包含 ToClash 规则 |
| sing-box JSON | 已验证的连接配置，不承诺完整迁移 Mihomo 规则 |

新订阅 URL 只显示一次，保存到客户端；遗失后轮换，旧 URL 失效。撤销、过期或管理员密码改变也会使旧地址失效，恢复备份后须重新交付。订阅授权不能调用管理 API。分流保存后刷新原 URL 获取最新已保存版本，自动刷新频率取决于客户端。

## 分流与 DNS

“分流与订阅”采用固定 ToClash 0.3.8 语义：

| 模式 | 默认行为 |
| --- | --- |
| 常规 | 本机与内网优先直连；自定义及服务规则后，中国大陆直连，其他交给 PROXY |
| 默认直连 | 明确指定的服务与域名走 FORCE_PROXY，其他 DIRECT |

PROXY 可选择 AUTO、DIRECT 或节点，FORCE_PROXY 不含 DIRECT。相邻 REJECT 规则阻止继续匹配时落入直连，不是所有连接失败的通用回调。常规模式依赖客户端可用的 GeoSite/GeoIP 数据，服务器不保证客户端远程库可下载。

40 项服务目录按需开关，保留原四项默认选择；服务域名列表不是完整流量发现器，关闭服务开关不表示强制直连。自定义域名、父子域覆盖、CGNAT 与企业内网 DNS 应在预览中核对。

草稿、预览、保存分开，预览不改变订阅。发生修订冲突应重新载入并合并，不覆盖其他页面更新；已保存文件损坏时不会悄悄回到默认规则。

## 高级协议限制

以下是公开使用的简要限制，完整字段和客户端边界以[兼容矩阵](COMPATIBILITY.md)及各专题契约为准，不表示同一协议的全部核心或传输组合都可用。

### Trojan / VMess 的 TCP + TLS

公开组合限 sing-box、原生 TCP、TLS、单用户和正常证书校验。Trojan 使用单密码，VMess 使用单 UUID；支持相应 URI/Base64、Mihomo YAML 和 sing-box JSON。服务端证书路径与私钥不导出；多用户、未知字段、关闭验证或额外传输不会靠丢字段通过。

## 0.4.3 VLESS/WebSocket/TLS 基线

sing-box / VLESS / WS / TLS 使用单 UUID、空 flow、明确 SNI 和正常验证。填写字面 path，遵守严格路径校验，不把 query 或百分号转义手填为 path。TLS ALPN 省略或恰为 `http/1.1`，可选 Chrome 指纹；early data、额外 headers 和未知字段不在公开范围。

可选 Host 是客户端路由信息，独立于 TLS SNI。固定 sing-box 不把 Host 作为服务端鉴权条件，修改合法 Host 仍可连接不代表 TLS 失效。三格式保留 path、Host 和 TLS 语义，详见[WS 已验范围](VLESS_WS_CLOSURE_043.md)。

## 0.4.4 VLESS/gRPC/TLS 基线

sing-box / VLESS / gRPC / TLS 使用单 UUID、空 flow。`service_name` 必须是 1–128 个 `[A-Za-z0-9._-]` 字面字符，区分大小写，不 trim 或添加 `/`、query、百分号转义。TLS ALPN 省略或恰为 `h2`，可选 Chrome 指纹；authority/Host、额外 headers、timer 与多模式不在支持范围。

固定 sing-box 使用 gRPC Lite，错误 CA/SNI 可能只让调用者等待到超时；超时本身不足以判断原因，不关闭验证。三格式保持 service name 和 TLS 配置，详见[gRPC 契约](VLESS_GRPC_044.md)。

## 0.4.5 Hysteria2/TLS 基线

使用 sing-box、单密码、明确 SNI、正常 TLS 验证与原生 QUIC 默认值。密码空输入时新建生成、编辑保留；非空密码须为 1–256 个有效字面字符，不接受全空白或控制字符。obfs、hopping、带宽、ALPN/uTLS 覆盖和多用户不在严格公开范围。

主机与云入口须允许节点 UDP 端口；已验证负载是 HTTP/TCP，QUIC 可连不表示应用 UDP 已验证。详情见[Hysteria2 契约](HYSTERIA2_045.md)。

## 0.4.6 TUIC v5/TLS

使用 sing-box、单 UUID/密码对、原生 QUIC、明确 SNI 和正常证书验证。服务端 ALPN 必须恰为 `h3`，不能省略；拥塞为默认 cubic、relay 为 native，零 RTT 关闭，不额外添加调优或指纹。UUID、密码分别空输入时新建生成、编辑保留。

支持 Mihomo YAML、sing-box JSON 和固定 Mihomo 导入器支持的非官方 TUIC URI 约定。固定 Mihomo TUIC adapter 硬编码 UDP 能力，不能靠无效的 `udp:false` 声称关闭 UDP；应用 UDP 未获验证。详情见[TUIC 契约](TUIC_046.md)。

### REALITY / Vision

限定 sing-box / VLESS / Direct TCP、精确 `xtls-rprx-vision`、Chrome、单 UUID、明确 SNI 和一个规范 16 位 hex short ID。X25519 公私钥须为解码后 32 字节的无 padding base64url 且相互配对；私钥仅在服务端保留。

参考握手端须支持固定核心的 TLS 1.3/X25519，它独立于应用目标。REALITY 不绑定普通托管证书，不加 ALPN 覆盖。三格式仅输出必要客户端信息；URI 导入器的 UDP 默认值不能被描述为已关闭应用 UDP。完整边界见[REALITY 契约](REALITY_VISION_047.md)。

### XHTTP / HTTPUpgrade

目前只有固定核心能力刻画，**公开导出保持阻断**。已有表单、配置生成代码或 parser 接受不构成公开支持；不能删除不支持字段、换成其他传输或退回 DIRECT 来声称兼容。研究及失败证据见[XHTTP / HTTPUpgrade 刻画](XHTTP_CHARACTERIZATION_048.md)。

上述协议说明不代替真实客户端连接验证。当前版本**浏览器未验证**；原入口快照和阶段验收见[历史索引](history/README.md)。
