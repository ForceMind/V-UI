# 停机备份的私有文件缓存

[071 完整基线](LOW_RESOURCE_071_BASELINE.md)的大日志场景首次在停机备份触及 512 MiB。生成 256 MiB 非稀疏日志后，完整服务组 current 为 461189120 字节，file 为 380387328、anon 为 59830272；备份后累计峰值为 536870912。阶段末分项不能冒充峰值同步分解，但足以指向文件缓存，而非直接断言 Python 大对象泄漏。

实际 `backup()` 先复制到私有临时目录，再对副本生成 manifest、流式压缩并计算新归档摘要。071 的助手磁盘目录固定假数据诊断中，复制后原日志与私有日志各驻留 256 MiB；压缩完成但副本未删除时，新 ZIP 还驻留约 84.2 MiB，而进程 RSS 高水位约 21 MiB。这是逐文件 mincore 离散读数，不是连续峰值、cgroup 归属证明或受限验收。

## 改动边界

- 源 data 仍普通读取，停止锁、独立副本、SQLite backup、完整性检查与排除规则不变。SQLite 分支及数据库副本没有新增 cache advice。
- 只为本次流式复制的普通私有文件逐次写回，以及其 manifest 摘要、压缩读取和新 ZIP 写入 / 最终摘要使用已有 8 MiB 批次 helper。通用 create_archive 默认关闭，不凭 metadata.kind 自动开启。
- ZipFile 关闭、回写中央目录后再次 finish / fsync；保留文件同步、目录同步与完整摘要。advice 不支持或失败只失去优化，真实 I/O、fsync 或摘要错误仍失败。
- 私有备份 ZIP 在目标目录下的 0700 临时目录内完成，成功后通过同文件系统硬链接无覆盖发布。目标已出现则失败，不覆盖；失败只清理私有目录。发布后目录 fsync 失败会报告失败并保留已完成文件，不通过公共路径删除来回滚。
- 目标文件系统需要支持硬链接；不支持则安全失败，不静默换成覆盖式 rename。这是性能候选的新边界，不假定冻结 0.4.7 的现有包已经包含。

不清理全局缓存，不对源数据、旧归档或恢复后的用户文件发出新提示，不把任何产品 / 验证进程移出原账本。操作停止锁不等于对任意外部写入者的跨文件原子快照保证。

## 审查、草稿与验证

首份 WIP `e8728f2b35295cf35feef63bd7c9ff0713283905` 的失败清理曾使用 lstat → unlink。独立审查确定性复现检查后目标被替换、清理误删 replacement；保持原 fd 只能防 inode 复用，不能防路径替换。该草稿未进入候选。修正 WIP `4a29b6eeda88e75c84f6c96a8f8d75bd18db39e8` 改为私有归档完成后无覆盖发布，消除公共路径清理。

14 项新测试覆盖 fd / inode 提示边界、源和数据库不冷却、关闭后的尾部写回、压缩后仍大于 8 MiB 的 ZIP、中途 / 摘要 / 目录同步失败、并发和既有目标保护、无提示 fallback、源替换后的副本一致性、坏摘要与恢复撤权。原安装 helper 一致性和恢复数据不冷却合同保留。修正全量本地 655 项：530 通过、125 环境 skip（44.580 秒）；独立 57 项专项及代码审查无剩余阻断。固定 ZIP 时间的独立比较确认 071、通用路径和私有路径的相同输入归档字节 / SHA 一致。

原始本地记录位于 `tests/benchmarks/results/*backup-cache*.json`。旧草稿记录仅保留过程；修正版必须自己的原件和准确提交 CI。逐文件驻留会受内核 readahead / LRU 时序影响，不承诺任何单次提示精确回收或固定内存上界。

修正版两次固定输入诊断中，源日志都保持 256 MiB 驻留；复制结束的私有日志分别仍有 16 / 80 MiB 驻留，不能称被严格限制到 8 MiB。压缩及摘要结束后，私有日志和新 ZIP 两次都为零驻留。后一对比使用同一 probe SHA，071 / 修正后的 wall 为 5.864646 / 6.012661 秒，CPU 为 5.863798 / 5.985959 秒；进程 rusage 的 512 字节输入块计数为 0 / 1057656、输出块为 697328 / 697488。减少重复缓存会带来重读 I/O，这次本地单次比较不证明固定速度或功耗收益。各次均验证原日志摘要未变、坏摘要拒绝、恢复后节点与大日志正确、旧会话 / 订阅撤权以及旧数据保留。

最终 512 MiB、1000 节点 / 大规则、256 MiB 日志、备份恢复与拒绝 / 清理验收仍待准确候选运行。即便备份阶段改善，也须单列后续坏摘要、恢复及验证读取产生的页缓存；不能把某阶段改善写成全生命周期余量或原卡达标。
