# V-TS-03：私有管理入口设计与阻断条件

已有 [V-TS-01 方案](TAILSCALE_MANAGEMENT_OVERLAY.md)与 [C0–C8 / R0–R4](TAILSCALE_MANAGEMENT_ACCEPTANCE.md)负责安装共存、原 URL 路径和基线恢复，本文件不重复它们。V-TS-02 只读观察器已由 [PR54](https://github.com/ForceMind/V-UI/pull/54) / [PR55](https://github.com/ForceMind/V-UI/pull/55)完成软件收口；真实 Tailscale 状态与共存仍未测。状态卡片不能批准本方案或驱动安全动作。关闭 V-TS-02 观察、unknown/stale 或停止 Tailscale 都不等于退出私有模式，不能解除隔离。

## 1. 保护目标与威胁模型

目标是：在明确选择的部署上，**整个面板 HTTPS 服务只能经获准的私有管理路径到达**，公网及未授权设备不能访问它；已有 VLESS 等业务入口及 direct/relay TCP 合同不随之改变。不是“服务器所有端口都私有”，也不是只隐藏 `/ui`。不保证匿名、零中断、始终在线或抵抗已控制主机 root 的攻击者。

| 威胁 / 失误 | 必须保留的防线与证明 |
| --- | --- |
| 公网扫描、遗留 IPv6、旧代理/NAT/第二监听绕入 | 精确监听清单、双栈网络入口限制与独立公网负向；只改 DNS 或成功连接 tailnet 不够 |
| 未授权 tailnet 成员、共享设备或过宽旧规则 | 核对全部有效 grants/ACL 与共享/标签授权，指定来源身份、目标机器和面板 TCP 端口；不能只添加一条窄规则就认为旧宽授权消失 |
| 获准设备被窃、会话被盗、恶意网页/伪造头 | 仍要求 V-UI 登录、会话、写请求 Origin/自定义头、TLS；Tailnet IP、用户名 Header、设备在线不授予管理员权限 |
| daemon 离线、地址变化、冷启动顺序或规则丢失 | 不回退公网/通配监听，不自动放宽规则、不自动换地址；无法证明隔离则阻塞启用或进入已评审的维护恢复 |
| 锁出后误用恢复、升级恢复旧公网设置 | 独立带外入口、确定的转换记录与离线恢复点；退出私有模式和重新开放公网是两个不同决定 |

信任边界包括受控主机管理员、实际 tailnet 策略管理者和被选管理设备；这些权限的泄漏不能由只读状态 API 解决；已获准设备与有效应用会话同时被控制时，本设计不额外提供用户身份保证。业务凭据、会话、订阅令牌及原始网络证据仍私有，只公开脱敏结果、计数和摘要。既有令牌持有人不能因私有通道获得新节点授权。

官方文档说明新建 tailnet 的默认策略可允许设备间通信，ACL 不约束设备的本地网络路径，故不能把“已加入 tailnet”视为最小授权或公网隔离：[ACL 边界](https://tailscale.com/docs/features/access-control/acls)。实际规则语法、来源身份/标签和传播行为必须按选定版本及有效策略另审，本设计不提交策略片段或设备授权。

## 2. 选定研究方向与不采用的捷径

选定供后续评审的最小方向：**原 HTTPS origin + 单个明确 Tailnet 地址监听 + 独立主机入口限制 + 最小有效 tailnet 授权**。不新增反向代理或身份代理，不迁移域名/端口/Cookie，不让面板自行管理 VPN。它目前被第 3 节的集成缺口阻断，不能据此直接修改现有配置。

- 沿用原域名、证书、端口、SNI、Host、Origin；管理端定向解析及 A/AAAA、DoH、代理、缓存核验复用 V-TS-01 候选 A。服务器解析与业务客户端解析不随之改动。
- 现有 `app.serve` 只接受一个字面 IP。首个候选只选择一个已核实的地址/地址族；不默认为双栈或新增多监听。另一地址族及所有公网地址仍要做拒绝测试，不能留通配 socket 作为备用。
- 精确 IP 绑定不是接口身份认证，也不能单凭它证明 NAT/转发/其他接口路径被拒绝。未来主机策略必须约束实际入站路径、目标和端口，与 tailnet 授权共同验证；不能把整个 CGNAT/IPv6 地址段当可信管理员。
- 网络约束由另行授权的系统管理面维护，不向面板加 root、sudo、socket/组权限或网络 capability。只读观察器的 online/unknown、30 秒缓存或权限不足不得成为放行/回退依据。
- Tailscale 默认 netfilter 规则及其顺序维护会与其他规则相互作用，不能假定追加规则一定先执行：[官方 netfilter 行为](https://tailscale.com/docs/reference/netfilter-modes)。具体 hook/优先级、IPv4/IPv6、已有连接和重启持久性须在指定系统证明；本设计不建议切换 netfilter 模式、flush 规则或关闭安全机制。

不采用：只隐藏导航/改公共 DNS；仅以来源 IP 或转发头免登录；通配监听加一个状态卡片；未知时自动公网回退；Serve/Funnel/新 MagicDNS origin；跳过 TLS 验证；新建第二面板进程共享同一数据库。后几类要么不满足当前安全目标，要么涉及独立 TLS/进程/数据设计，不是本轮实现范围。

## 3. 当前代码证明的集成阻断，不虚构现成开关

| 当前事实及来源 | 对后续工作的约束 |

| [scripts/install_system.py](../scripts/install_system.py) `https_health()`：按 bind 地址族连接 `127.0.0.1` / `::1`，验证原域名链并要求 401 | 精确 Tailnet IP 监听不满足现有回环健康检查。未来若单独批准兼容实现，必须仍验证所选实际监听、原 SNI/Host、证书和未认证 401；不能加回公网/回环第二监听、用 `-k` 或假健康结果换绿 |

| [main.py](../main.py) startup 恢复核心，shutdown 停止证书任务及所有核心 | 停/重启面板不是无业务影响的管理隔离开关。启闭转换必须安排明确维护中断；不能在 tailnet 状态变化时无条件重启面板并声称业务不断 |
| 同一 main app 包含 [公开订阅路由](../app/api/subscriptions.py) `/sub/{token}/{output_format}`，以及登录页/静态页面/管理 API | 整个 HTTPS 端口私有化也会使公网订阅刷新不可达，合法 token 不绕过网络限制。若用户要求公网订阅继续可用，本候选阻塞；另建公网订阅 origin/服务属于未来独立设计，不偷偷做路径例外 |
| [HTTP-01 responder](../app/certificates/http01.py) / 服务生成器是独立挑战入口；证书续期任务仍由面板启动 | “面板私有”不等于关闭全部公网端口。既有 HTTP-01 的 TCP 80、域名解析、挑战响应与续期可达性必须另行明确保留和验收；不能假定 provided 证书就让安装器不启动该服务。完全不留公网 HTTP 的目标需另审证书生命周期，不顺带实现 DNS-01 |

这些是静态源码结论，不是实机故障复现。设计认可不消除阻断，也不授权现在实施上表的代码或系统变更。

## 4. HTTPS、认证与数据不变量

依 [认证中间件](../app/middleware/auth.py)与 [登录 API](../app/api/auth.py)，以下必须原样保持：

1. TLS 在原域名/证书/SNI 上成功；错误证书或名称在 TLS 层失败。不接受 insecure、客户端忽略警告、伪造 `X-Forwarded-*`。
2. 受保护请求 Host 必须符合规范化 origin；错误 Host 403。正确 Host、无会话的受保护 API 401，`/ui` 文档可 303；不能把公开静态页面本身存在误报为登录绕过。
3. 登录及已认证写请求要求精确 Origin 和 `X-VUI-Request: 1`；错误/缺失为 403。无会话受保护写请求先 401，GET/HEAD/OPTIONS 不套写请求 Origin 断言。
4. HTTPS 会话 Cookie 继续 `__Host-vui_session`、Secure、HttpOnly、SameSite=Strict、Path=/ 且无 Domain；保留过期、退出和已有撤销机制。网络迁移不自动轮换/生成凭据，也不承诺旧会话立即失效；若要求会话撤销，须列为额外明确动作与验收。
5. 公开 `/sub` 继续独立 bearer 授权/完整实例绑定检查，不改为管理员 Cookie 模式；私有后仅额外受到同端口网络不可达限制。不重写 URL 中令牌、不恢复已撤销授权，不在访问日志记录它。
6. 不改变节点监听、导出字节、单 selected_upstream、固定核心或有效 relay UDP 拒绝；自身地址进入策略身份的恢复保护不削弱，见原 C3/C7。

## 5. 启用、退出与锁出：人工双阶段模型

下列名称是审阅状态，不是配置键/API。未来操作者必须记录准确软件/规则/配置摘要、阶段、时间和预期影响；不明结果先检查，不盲重放。**当前没有实现跨服务/规则的原子事务或自动回滚器。**

| 状态 / 转换 | 必须满足的条件与失败处理 |
| --- | --- |
| 原基线 → 准备完成 | 原配置不变；完成 C0–C8/R0–R4，确认订阅私有化选择、证书安排、维护中断、带外恢复和具体动作授权。带外不可用或健康/升级缺口未解决则停在原基线，不开始转换 |
| 准备完成 → 入口封闭维护 | 先建立并证明不会随 daemon 重启失效的限制，处理原公网已建立连接，再在受控维护窗口转换监听/配置。每个中间态不得新开放公网；仍存旧连接或规则结果不确定就不进入下一阶段 |
| 入口封闭维护 → 私有已验 | 由独立获准管理设备以原 URL 完成 TLS/登录/实际路径验证；由独立公网及被拒设备验证隔离；核旧监听/连接、准确配置与业务恢复。缺任一证据只记维护/阻塞，不能因面板启动或 status online 标成功 |
| 私有已验 → 管理路径故障 | 持续保留隔离，不改 bind/origin、不放宽规则、不自动 apply/reconcile。连接/地址丢失只证明可用性变化，不自动意味着核心已停或公网已开放。经带外判断影响与恢复，已有连接单列 |
| 关闭私有管理 / 撤销接入 | 首先明确是仅撤销管理设备、停止管理入口，还是退出整个私有模式。撤销/停止不自动恢复原公网；若必须停面板，应明确连同核心/续期受影响，不伪称管理独立停机 |
| 显式恢复原公开基线 | 这是重新暴露面板的独立决定，须明确授权具体地址/端口和影响。先保留隔离恢复原受信配置/证书与策略，验证健康/恢复，再按已批准差异释放限制；不定时自动开放。无法验证保持维护状态 |

恢复只撤销本次明确记录的差异，不能恢复整份陈旧防火墙覆盖并发合法变更，不 flush、不删除数据库或快照。服务配置、网络策略和完整数据备份是不同恢复对象；恢复应用包/数据库不证明系统规则也恢复。完整数据恢复仍遵守停机、journal、旧目录保留和会话/订阅撤销纪律。

对需要上游的活动策略，自身地址集合变化可能导致 `RECOVERY_REQUIRED`；这是保护拒绝，不是共存成功。不能忽略 `tailscale0`、修改活动元数据、伪造地址或自动重应用。地址无法合理恢复时保持停止/阻塞，由带外负责人另作明确决定。

## 6. 故障拒绝与连接语义

私有隔离是网络/监听属性，不等于“控制平面在线”。daemon 停止、控制平面不可用、设备到期/撤销与客户端网络切换是不同事件；必须分别测新 TCP、已建立 TCP、HTTP keep-alive、已认证会话与新登录，记录实际拒绝层和时延。不能仅用状态卡片变化或单次超时证明授权已经撤销，也不能承诺瞬时撤销已建立连接或召回已下载配置。

接口缺失/换地址时不得自动选择公网或另一个接口；不自动修改管理员批准的地址。冷启动、服务重启、升级/回滚、配置丢失/损坏都必须保持公网拒绝，缺少隔离前置证明时不能启动面向公网的备用配置。具体持久规则、启动屏障、已有连接处理和故障后的安全动作尚待按目标系统实现及验证，未解决就不具备启用资格；本轮不会写 watcher 或把只读采样升级成控制器。

若发现隔离规则失效、出现未授权响应或状态不明，停止推广并走带外事件处理；不得把“停止整个面板及核心”隐去业务影响，也不得以业务连续为由开放公网。主机 root 恶意篡改不在本设计可防御范围，正常重启/升级丢失规则则在验收范围内。

## 7. 后续可执行验收门槛（均未运行）

先复用原 C0–C8/R0–R4 的环境与证据模板，不复写其全部用例。新增下列 **P** 矩阵专门证明私有化；执行命令、规则位置和恢复程序须在另行获准的目标系统评审后确定，本文件不给跨系统粘贴命令。

| ID | 场景与明确通过条件 |
| --- | --- |
| P0 范围确认 | 用户明确全 HTTPS 服务含订阅转为私有、原 URL/证书不迁移、维护中断；固定软件/包/核心/Tailscale/OS/init/防火墙版本，实际带外入口和可读恢复点已验证 |
| P1 入口清点 | 列全 IPv4/IPv6 socket、公网/内网/tailnet 路径、旧代理/转发及同机域名用途；所选私有地址准确，所有其他入口与第二监听被证明拒绝；不能只测 IPv4 |
| P2 授权正负向 | 获准设备原 URL 正向；独立公网/局域网/未授权 tailnet 设备负向，对静态页、受保护 API、登录和持有合成有效令牌的 `/sub` 同时核不可达。结合服务端入口/规则计数与监听证明拒绝，超时单独不足；公网 TLS 握手或任何应用 401/403/404 响应均不能判私有隔离通过 |
| P3 应用边界 | 在允许路径测试第 4 节全部 TLS/Host/Origin/Cookie/退出/撤销边界；网络许可不替代应用认证，应用 401/403 不冒充公网已封闭 |
| P4 转换/残留连接 | 从原基线与每一中间态注入可恢复失败；旧公网 TCP/keep-alive/会话与新连接分别验证。私有确认前旧公网通路已封闭，无隐藏自动公开回滚；只撤销本次变更且保留失败记录 |
| P5 生命周期 | daemon 重启、控制平面断连、接口/地址新增消失、许可撤销/到期、面板先后启动及整机冷启；记录新/旧连接实际行为，永不切公网/通配。缺测一种就不授该条件资格 |
| P6 运维全链 | 私有状态下安装/升级拒绝或明确支持、stage/activate/回滚/备份恢复/中断恢复和系统重启逐项验证；健康检测真实目标+原 TLS/SNI/Host+401，不重开面板端口或静默换配置；记录面板与业务共同停启影响 |
| P7 证书/订阅 | 既有 HTTP-01 挑战入口和真实续期/热加载（或明确人工证书生命周期）独立证明；无挑战内容不能被当作面板代理。私有客户端可刷新订阅，公网刷新按已确认取舍拒绝；实例绑定/撤销不变 |
| P8 业务与身份 | 复用 C3/C7 的四状态和每入口三态、同/异自身地址集合、真实原因/零误送达/无 DIRECT；不改策略绕过 `RECOVERY_REQUIRED`，停机及恢复结果如实记录 |
| P9 退出/锁出恢复 | 在失联管理端条件下由带外完成仅撤销、保持私有恢复以及获单独许可的公开基线恢复；逐项网络/数据/证书/业务验后，不能只证明重新登录；V-TS-01 R1 的公网 URL 恢复不是本阶段默认恢复 |
