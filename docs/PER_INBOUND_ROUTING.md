# 同一实例使用直连节点与中转节点

## 适用范围

这是每入口三态 TCP 的**未发布候选功能**使用说明；准确提交的验收、失败与剩余事项见[当前开发状态](DEVELOPMENT_HANDOFF.md)。公开 v0.4.8 安装器基线不含此功能，本文不表示已发布或全部验收完成。

本轮显式策略限于同一 sing-box 实例的 VLESS、直接 TCP、正常验证的 TLS、空 flow、单 UUID、无定时过期；其他协议/传输不能靠选择“指定直连”或“指定中转”获得新资格。入口条件与上游条件不同：已支持的 REALITY/Vision 上游不表示本轮 REALITY 入口也可显式覆盖。手机真机、VPN/TUN 和真实运营线路仍须独立验证，不要求自研客户端或替换官方核心。

## 三种策略怎么选

在“入站节点”点“添加节点”或“编辑”，使用“已保存路由策略”：

| 选项 | 该入口成功应用后的行为 |
| --- | --- |
| 跟随全局（默认） | 随“默认入口中转”开关：关为普通服务器出口，开为中转 |
| 指定直连 | 客户端 → 此入口服务器 → 目标，不随默认开关改变 |
| 指定中转 | 客户端 → 此入口服务器 → 唯一已选上游 → 目标，不随默认开关改变 |

“直连”指服务器的普通出口，仍保留既有路由、拒绝规则和能力。它不是让客户端绕过此节点直连目标。“服务器本机显式代理”只控制服务器上明确使用该 loopback 代理的程序，与各入口策略独立；关闭两个开关也不会关闭“指定中转”节点。

所有中转节点共用一个“唯一上游”，本轮没有每节点上游选择。开启本机代理、开启默认入口中转，或存在启用的指定中转节点，都需要合法上游。上游失效时有效中转失败关闭，不回退为此入口服务器直出；有效中转仅 TCP，服务器拒绝应用 UDP，普通直连既有 UDP 能力不被统一关闭。

## 第一次只建直连节点，不需要上游

1. 在“入站节点”添加符合上述条件的节点，选择“指定直连”，填写端口、SNI 和有效证书，保持证书验证，点“创建并应用”。
2. 如果实例还没有活动配置，会提示设置已保存但核心未应用，列表显示“已应用出口未确认”。节点已经保存，不要重复新建，也不必配置海外上游。
3. 进入“代理与中转”，保持两个开关关闭且不选上游，按下节检查、核对并应用。返回节点页点“刷新节点”，确认显示“已应用普通直连”，再测试实际连接。

若已有活动配置，节点创建/编辑会尝试按该活动配置应用；它不会顺带应用代理页尚未提交的草稿。

## 第一次建立中转节点

1. 在“代理与中转”点“导入 URI / JSON / YAML”，选格式并输入合资格上游，点“预览可导入节点”；明确选择候选并确认不导入的区块后，点“保存所选上游”。若上游来自另一 V-UI，使用其[专用 TCP 上游导出](TCP_UPSTREAM_EXPORT.md)。
2. 在“唯一上游（必须明确选择）”中选中它，点“保存草稿”，再按下节核对并应用。**两个开关可以始终关闭**；导入成功不等于已选择，保存草稿不等于已应用。
3. 在“入站节点”新建或编辑合资格节点，选择“指定中转”，启用并点“创建并应用”或“保存并应用”。也可先将节点状态设为“停用”保存草稿，准备好后再启用。
4. 点“刷新节点”，确认“已应用中转（仅 TCP；UDP 拒绝）”。启用前若尚未应用合法的已选上游，服务器会拒绝，不会用未应用草稿或直出代替。

已有活动上游的节点变更沿用该活动选择；要更换所有中转入口的出口，先在“代理与中转”明确选择、保存并应用新的上游。检查仅确认配置、入口资格和地址条件，不证明上游认证或业务可达。

## 保存、检查、核对与应用

“代理与中转”按以下顺序操作：

1. 改动开关或上游后先点“保存草稿”。未保存编辑不会改变活动配置，并阻止检查/应用。
2. “检查已保存草稿”可查看入口、地址与核心配置结果；检查不会应用，也不会验证 TLS 握手或业务连接。
3. 点“检查并核对应用”，在“应用前核对”中确认所选上游、每个启用入口的有效策略、资格及短暂中断提示，再点“确认以上内容并应用此修订”。该步骤会重新检查；“取消本次核对”不发送应用事务。
4. 等待页面重新读取并确认活动修订，再到节点页核对“已应用出口 / 状态”。需要改配置、发生冲突或刷新后应重新核对，不能沿用旧检查结果。结果不确定时按页面提示“刷新服务器状态”或重试同一次应用，不连续发起新事务。

节点页“已保存策略”是期望值，“已应用出口 / 状态”才是运行状态声明。“待应用；当前出口未确认”、未确认或 `dirty` 都不能当成新策略已生效；即使核心还显示 Running，也可能仍是旧配置。修正明确错误后重新检查/应用，必要时按[故障排查](TROUBLESHOOTING.md)与[受控离线恢复](DUAL_PROXY_RELAY_OFFLINE_RECOVERY.md)处理。无法确认安全恢复时核心会停住，不转普通直连。

- 在编辑器把“节点状态”设为“停用”并保存，是对该节点的期望变更，须核对应用结果。
- 在新显式策略下，手动停止的核心不会因节点保存或证书续期自行启动；恢复服务需明确执行核心重启并复核。停止不清除中转保护意图。
- **删除保存但应用失败时，旧入口可能仍可用**，即使数据库列表已没有该行。不要把删除提示当成即时撤销；核实运行状态，必要时明确停止受影响核心，再修复并应用。

## 客户端选什么导出

- **普通“分享”或“分流与订阅”**：给现成客户端导入标准 VLESS 节点。为直连/中转入口分别设置易认的备注，导入后选择对应节点；服务端按该入口的已应用策略决定第二跳。备注只是标签，不决定路由，也没有私有 URI 路由参数。节点连接信息不含海外上游 UUID 或本机代理密码。普通订阅的客户端分流规则仍生效，只有实际经所选节点的流量才进入此服务器策略；普通导出成功不是已应用出口证明。
- **“严格中转配置下载”**（代理与中转页）：用于需要无 DIRECT 候选、经代理业务 DNS 的独立客户端完整配置。填写所选入口 ID 与入口公网 IP，下载严格 Mihomo YAML 或 sing-box JSON；要求该入口已应用中转且正在运行，指定中转在默认开关关闭时也可使用。直连、停止、节点配置与活动策略不一致或无法确认时拒绝。较新的代理草稿不会进入下载。它不启 TUN、不修改系统 DNS，也不代替设备端到端验证。
- **“导出为中转上游（仅 TCP）”**（D1）：供另一 V-UI 实例导入为其上游，输出 URI 或单节点 YAML。它不是普通设备导出或严格中转完整配置；不能因普通分享含 UDP 字段而手工删字段冒充合资格上游。

所有下载/分享都可能含所选节点的连接凭据，请妥善保管。用客户端分别选择节点访问受控 HTTPS 目标并确认出口；只看配置检查、节点备注或面板 Running 不足以验证端到端路径。

## 升级与回退

旧数据库缺少策略字段时会迁移为“跟随全局”，保留既有节点信息。首次尝试保存显式策略会先写入新格式能力标记，防止旧程序忽略策略后直出；已核验的旧 a98 程序会拒绝读取。即使后续节点保存失败，或之后改回“跟随全局”，也不会移除已写入的保护。不要手工改标记、丢弃字段或删除数据库来强行降级；备份/恢复须保留完整关联状态，并走支持该格式的[受管运维流程](OPERATIONS.md)。
