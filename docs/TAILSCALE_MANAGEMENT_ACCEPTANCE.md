原始网络/策略证据仅存私有受控目录；公开记录只放脱敏摘要、计数、错误码、时间、哈希和结果，不包含真实地址、UUID、账户、密钥或完整配置。

## 2. 最低共存矩阵（全部未运行）

先建立两个可还原实验基线：B0（无 Tailscale 时已应用的业务策略）和 B1（接口稳定存在后在实验中明确建立的业务策略）。建立 B1 是实验操作者的显式动作，不能由状态卡片或接口变化自动触发，也不能用于把 B0→安装失败改判通过。覆盖 host proxy 开/关 × 全局 relay 开/关四状态，并至少包含启用的每入口 inherit/direct/relay；双全局 off 时 explicit relay 仍按有效策略保护。使用既有固定核心和单 selected_upstream，只验已有 TCP 合同。

| ID | 计划操作 | 必收证据与判定 |
| --- | --- | --- |
| C0 安装前 | 在 B0 下采集控制基线与带外可用性 | IPv4/IPv6 地址、全路由表/策略规则、默认路由、DNS/解析器/代理、监听、防火墙链/规则优先级、业务来源与策略修订；备份可读且摘要固定 |
| C1 安装/连接 | 独立实验安装、授权登录并接入默认管理 tailnet；不启出口/子网路由 | 与 C0 逐项比对 netfilter/路由/规则/fwmark/DNS/监听/地址变化，分类预期 overlay 变化与业务影响；不得承诺零系统变化；检查 CGNAT/现有 VPN 冲突 |
| C2 URL/鉴权 | 按方案候选 A 在专用管理端保留原 HTTPS 域名/端口/证书 | 浏览器实际 Tailnet 目标地址、双栈路由/服务端到达证据、SNI/TLS、Host/Origin、登录/退出/会话；按下方校验层分别记录 TLS、Host、登录/写请求 Origin/自定义头、无会话及未授权设备的拒绝。覆盖 A/AAAA、缓存、DoH、代理 DNS；不得关闭 TLS 校验 |
| C3 业务与故障 | 安装前/连接后比较上述策略组合；用隔离假上游模拟失效 | 已允许 direct 与 relay TCP 的独立目标来源、入口/上游计数、导出字节/摘要、desired/applied/active/核心修订；受保护中转失效有明确拒绝原因、零目标送达、无直出/无 tailnet 替代出口。超时本身不是拒绝证据 |
| C4 接口生命周期 | B0/B1 分别覆盖连接、down/up、断网重连、daemon 停止/重启及地址新增/消失 | 每次记录实际接口/地址集合；`tailscale down` 不保证接口消失，按事实区分。比较系统状态与自身地址快照，持续流量和新连接分开；只在实验授权下使用可恢复故障注入，不在主机随意删接口/规则 |
| C5 面板/核心重启 | 在地址稳定、变化、接口缺失三类状态分别重启面板、单独重启核心 | 记录重启前后地址、active/runtime_context、策略身份与核心状态、准确错误码/停止范围；不能以重启按钮成功或旧连接未断替代恢复验收 |
| C6 整机重启 | 覆盖 tailscaled 先就绪、面板先启动及 tailnet 离线的冷启动 | 带外入口可用，记录时间线/服务先后、地址集合、恢复保护、管理/业务可用性；出现 `RECOVERY_REQUIRED` 如实标失败/阻塞，不自动重编译或重应用 |
| C7 策略恢复 | 分别在自身地址相同/不同的环境验证已知旧快照启动、prepared 事务回滚及备份恢复 | 使用实验准备的可恢复状态和现有恢复纪律，记录来源/活动/核心修订、恢复计划摘要、journal 与错误；对需要上游、身份包含自身地址的活动策略分别记录同集合正向与异集合保护拒绝。无上游控制组记录既有正常行为，不将所有地址变化都预设为必须 `RECOVERY_REQUIRED`；不得篡改元数据或删除快照来通过 |
| C8 退出/回滚 | 执行 R0–R4，返回 B0 及 B1 各自已知网络/数据状态 | 对比 C0/B1 原始证据，验证 TLS/应用登录、监听/网络差异、TCP 来源和保护。保留所有中间失败；只重获面板访问不等于业务已恢复 |

C2 负向按校验层区分：证书/SNI 名称不匹配应在 TLS 校验失败；错误 Host 的受保护请求应 403；有效 Host 下未登录的受保护 API 应 401（UI 可 303 跳转）。登录或已认证写请求的错误/缺失 Origin、缺 `X-VUI-Request: 1` 应 403；现有 Origin/自定义头检查仅用于非 GET/HEAD/OPTIONS，不能要求 GET 只因错误 Origin 就被拒绝。未授权设备按已审阅的最小 tailnet 授权检查网络拒绝，不以应用层错误冒充网络隔离。

首轮选择独立电脑，不要求手机双 VPN。记录管理 peer 的 direct/DERP/Peer Relay/unknown 及变化；没有某连接类型的环境就标未测，不为强造结果改防火墙。管理链路类型不替代业务出口归因。

### 判定规则

- 安全不变量：不绕过 TLS/登录/Host/Origin，不误暴露新公网入口，不削弱自连保护，有效 relay 不静默直出，原始数据/失败证据可恢复。
- 共存通过：在明确的系统、提交、策略和 URL 条件下完成 C0–C8 与 R0–R4，所有业务不变量及人工恢复都成立。任何关键未测/跳过/未知均不算通过；不能推广至未覆盖系统或生产环境。
- 地址变化触发 `RECOVERY_REQUIRED`：若得到真实证据，只能判该条件下保护拒绝生效；业务可用性及安装共存仍失败/阻塞。不能通过自动 apply/reconcile、更换核心、忽略接口或改成双关默认值解决。
- 失败保留实际退出码、时间线、预期/实际、影响范围及恢复结果。后续相同字节重试必须单列 attempt，不能覆盖旧记录；静态推导不能填写为已复现。

## 3. 回滚演练（全部未运行）

以下是未来实验中的人工步骤要求，没有本轮可执行的网络变更命令。恢复脚本/命令、确切服务名和快照位置须先依据实验系统评审；不能把跨发行版的通用命令当成已验证手册。

1. **R0 停止推广并留证**：一旦失联、业务改变、策略拒绝或恢复不明，停止新的安装/配置/策略写入，通过已验证带外路径保存前后差异、错误与持久日志；不循环重启，不假定数据交换已经成功或未执行。
2. **R1 撤销管理端覆盖**：仅撤销本次添加的解析覆盖并处理相应 DNS/浏览器连接缓存，核原 A/AAAA 与实际连接。恢复公网 URL 可访问不证明 tailnet 测试通过。
3. **R2 恢复系统网络基线**：在带外会话中依据本次记录人工撤销新增的 Tailscale 连接/服务改动，并比对地址、防火墙、路由/策略规则、DNS 和监听。停止服务/卸载不保证规则或自身地址恰好复原；不 flush 防火墙、不关闭主机安全机制、不覆盖其他规则/既有业务设置。不能精确撤销时还原预先验证的实验主机快照，并记录其数据边界。
4. **R3 核对策略与数据**：B0 策略可能因新接口加入而拒绝恢复，B1 策略也可能因移除接口而拒绝。先恢复对应基线的实际地址/服务端面板解析条件，再按现有保护检查恢复；不能伪造接口/解析来“凑快照”。需完整数据恢复时，遵守[有界离线恢复](DUAL_PROXY_RELAY_OFFLINE_RECOVERY.md)的停机证明、明确备份、预览及摘要确认、journal 和旧目录保留纪律。离线数据恢复成功不保证随后启动/线路通过；地址条件无法合理恢复就保留停止状态，记录阻塞并转独立设计。
5. **R4 独立验后**：恢复后重新核验带外访问、证书/鉴权、原监听与网络、准确 active/核心修订和 direct/relay TCP 正负向。出现未决 journal、状态不确定或目标误送达，不宣称回滚成功。任何重新应用策略都是新的显式变更，需要独立评审，不能成为此安装计划的自动收尾。

本期保留公网面板原有暴露；公网不可达是未来 tailnet-only 的独立门槛，不能在 C8 擅自关闭端口或收紧规则。管理设备/面板端口最小授权也仅做设计，不在本轮改权限。
