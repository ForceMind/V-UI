# 受管终端控制（候选）

这层软件将固定的全局 `v-ui` 入口连接到受管服务及已有的版本、备份、恢复实现。它是独立于默认安装器的显式组件；不能因为包里出现源码就认为系统已经安装了这个命令。本文描述实现和验收边界，不代表已在用户主机安装，也不替代真实 systemd / OpenRC 和 root 安装资格。

## 安装消费点与信任

完整、独立可信且已验收的 release kit 包含 `install_ops_control.py`、`system_ops.py`、`ops_worker.py`、`release_tools.py`、`v-ui` 与对应清单和既有服务模板。审阅并独立确认整个 `SHA256SUMS` 文件的可信 SHA-256 后，显式安装命令为：

```sh
sudo /usr/bin/python3 -B -I -S ./install_ops_control.py --kit . --sha256 '<可信 SHA256SUMS 文件摘要>'
```

这条命令实际安装安全关键的 root-owned 文件，必须由主机操作者明确选择。当前开发只在云端临时目录中以非 root 假安装/假服务测试，不执行此系统安装命令。默认 `install.sh` 不调用新安装器，在线 `--version` 的固定下载路径也不自动添加这些组件；必须使用完整 kit，不能把服务用户可写 payload 当作 root 控制源码来源。

摘要验证字节完整性，不认证来源。安装器本体及 kit 必须在执行之前从独立可信来源接受；未知脚本内部的自验不能证明该脚本本身可信。安装器不新增账号、sudoers、SUID、capability 或常驻代理，不改变防火墙、SSH、服务启用状态或网络设置。新文件为固定的 `/usr/local/sbin/v-ui` 和 `/usr/local/lib/v-ui/` 下控制源码与 receipt；不向用户任意输入的系统路径写文件。

root 控制只用固定 OS `/usr/bin/python3` 的隔离模式、标准库和 root-owned 控制源码，并显式使用 `-B` 禁写 bytecode；`-I` 会忽略相关环境变量，不能仅依赖环境设置。需要受信、持续可用的 OS Python；缺失、不受信或不满足版本/标准库能力时拒绝，不回退到服务用户拥有的 portable runtime。服务配置中的 `bootstrap_python` 仅是已有降权服务的启动锚点，不能作为 root 解释器。安装后通过固定 `v-ui` 入口调用；不要绕过它直接用带任意环境、site hook 或其他解释器的 root Python 执行控制文件，后置检查不能撤销解释器启动前已经执行的钩子。

receipt 精确绑定安装记录、launcher、固定服务文件、控制组件、入口和 OS 解释器。控制器发现改动、缺失、多余路径、链接或不可信所有权/权限即拒绝。合法 OS Python 更新或旧安装器升级改变相关文件后，使用当前独立可信 kit 和上述命令的显式 `--refresh` 重新建立基线：既有控制组件仍须与旧 receipt 一致，当前解释器和安装文件须重新通过完整来源/模板校验。不能忽略 receipt 漂移、删除 receipt 或把未知 helper 改动重新背书。

如果控制组件发布中断且 receipt 缺失，只能在显式 `--refresh`、至少存在一个固定目标、每个现存目标都具备预期 root 权限/类型且逐字节匹配同一份已接受 kit 时补齐缺项；普通重试不自动接管。任何未知内容、链接或不同版本混合残留都拒绝，需要人工核查，不能声称任意安装中断都可自动恢复。此规则与用户数据库的 restore journal 分开，绝不为修复控制入口删除用户数据。

## 系统控制与事务

系统命令、服务名和环境固定。查询错误、未知状态、切换中、总线不可达或超时不是“已经停止”；状态快照也不是 HTTPS、证书或代理链路健康证明。所有写动作需在可信菜单内新输入确认。EOF、非 TTY 或确认前中断不开始写操作。

systemd 先停止 HTTP-01 socket，避免 responder 再次被 socket 激活，再停止面板和 responder 两个服务。除了服务停用终态，还验证固定 units 的 cgroup 没有残留进程；不只看 MainPID 或锁是否能获取。加载的服务需匹配固定 FragmentPath、无 DropInPaths、无待 daemon-reload、专用 User/Group、受管 KillMode 等约束。当前需要 cgroup v2；缺失或无法验证时拒绝写入。

OpenRC 现有 status 文本不能充分证明 core、certbot、watchdog 后代全部静止。当前仅查询状态；依赖停启服务的动作全部拒绝，不把一次 `rc-service stop` 成功等同于可安全恢复数据。纯候选准备不控制服务，可单独执行。各平台的代码/假服务测试与真实 init 生命周期验证分开记录。

控制层和旧安装器共用同一个固定 root 操作锁，拒绝并发。降权 worker 在服务停止前取得实例 `.operation.lock`，并持续持有到服务恢复、核验和最终握手结束。它在确认停服后再持有面板、两个核心与证书 worker 锁。恢复替换整个 data 目录之前，同时锁住旧 data 和暂存新 data 两代 writer 锁，避免只持旧 inode 而让新目录失去保护。

worker 只以既有专用服务 UID 执行包校验、候选健康检查、数据库和归档操作；root 不导入 payload 或读取用户数据树来执行逻辑。通信是有界的固定 JSON 协议，不是 shell，不接受 worker 返回任意 root 命令或路径。准备握手只表示前置校验和操作锁已取得，不表示 writers 已经停止。

候选准备是独立分支：本地路径和可信 SHA-256 不回显，明确确认后才启动；只取得操作锁，不查询/停止/启动服务，也不取得 writer 锁。它执行可信候选的同 UID 代码，工作期限 600 秒；正常 stage 健康检查返回并确认 CURRENT 原始字节和根目录身份保留，才报告候选已准备。READY 本身不是通过依据，准备不等于激活升级。超时或清理未确认可能留下不完整候选；不自动删除未知目录。此动作不隔离恶意包，也不承诺旧服务在任意资源压力下完全无影响。

stage 与 restore 输入文件必须由既有 `v-ui` 用户拥有且为 owner-only 的普通单链接文件，完整祖先链不能含符号链接。菜单不会以 root 代读 `/root` 下载目录，不自动复制、chown 或放宽权限；root 下载的 `0644` 文件即使摘要正确也不满足输入条件。

版本切换复用既有完整 payload/runtime 校验和独立候选健康检查，同一次操作锁内先生成私有停机备份，再原子选择 CURRENT。选项 `7` 同样接受已准备且已确认的旧版本 ID，实现显式代码回退；可用包内只读菜单 `2` 查询 CURRENT/previous ID。代码回退仍先备份，不恢复旧数据库，也不复活旧会话或订阅授权。成功后按原来 panel/socket/responder 拓扑恢复，不擅自 enable/disable；旧 bootstrap runtime 必须保留，不能因 CURRENT 已切换就删除它。配置中的安装 release ID 是历史锚点，不一定等于实际 CURRENT。

备份由 worker 生成私有目录和受限文件名，包含未加密的数据库、节点秘密、证书私钥及 CA 账号，必须自行妥善保管。恢复按既有逻辑保留原数据恢复目录，并撤销旧管理会话和订阅授权；第二次目录替换失败且 data 缺失时，既有恢复原语会把原目录归还原位。失败、超时、异常退出或 `RESTORE_PENDING.json` 不是成功。已确认停服后出现失败不恢复启动；停止命令本身失败时只执行有界再次停止并报告状态未确认，不能保证服务已经停止。root 控制层不额外回滚数据、删除未知目录、绕过 journal 或重启到未确认状态。

选项 `9` 是明确选择的 `recover-restore` 消费者，用于完成中断还原后的原目录恢复。只接受本实例私有、小于等于 16 KiB 的规范 journal，其中仅允许固定的 `recovery/before-<32 位小写十六进制>` 原目录；不会寻找其他备份或接受任意恢复路径。data 缺失时不创建空目录来掩盖故障，同时保护已存在的旧/当前两代 writer 锁，保留被替换的当前数据于新的 interrupted 目录。两个数据代都不存在、journal 不可信或恢复后的活动代码/启动锚点校验失败均拒绝。

此动作仍先按同一受信服务协议确认停止，成功后只恢复本次请求开始时的运行拓扑。若前一次失败后服务已停，这次恢复完成后仍保持停止，需要另选启动；不会猜测早先失败前的状态。它不是自动 journal 清理，也不绕过已有权限和备份校验。

这是受管服务和合作式 CLI 的一致性控制，不隔离恶意同 UID 代码、直接数据库写入或绕过锁的其他程序。不要同时运行直接 `app.admin`、`main.py` 或自写数据脚本。菜单受信检查也不将任意候选包变成安全沙箱。

## 验证层次

- 纯软件层：临时私有目录、真实文件锁/SQLite、已知合成包、假服务状态、协议失败、进程期限及 PTY 交互。
- 打包层：完整 kit 固定成员、哈希、安装消费者依赖闭包和四 target 原件分别检查。
- 系统层：真实新组件安装、降权、init 管理和故障恢复需要另行在明确为空的临时主机执行；此前旧安装器的 CI 不替代这一资格。
- 部署层：上述任何测试都不表示已经操作用户服务器或已公开发布。

准确提交的测试次数、失败和未执行项写入对应 PR 验收记录。未得到本层真实 root/init 证据前，不称此候选控制器可直接投入生产。
