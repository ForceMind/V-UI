## 目标与范围

用户要解决的是“配置和操作看不懂”，不是当前机器缺少一个上游。当前机器可能为另一台服务器提供出口；另一台负责接入和中转。新流程按用途组织，常用流程不要求理解核心、协议、传输、SNI、flow、证书路径或 inherit/direct/relay。

默认新建仅两种用途：

| 用户看到的用途 | 方向 | 完成后的主要操作 |
| --- | --- | --- |
| 给手机或电脑用 | 手机/电脑 → 本机 → 网站 | 分享给客户端：链接、二维码、订阅入口 |
| 给另一台服务器用 | 另一台服务器 → 本机 → 网站 | 复制给另一台 V-UI：仅 TCP 上游专用配置 |

“本机通过另一台服务器转发”留在其他用途/独立连接页面。只有进入此流程才索取另一台服务器的连接配置，显示连接方向、检查与应用结果。未配置上游时不假装已启用，不猜测上游，不创建回环连接。

不增加协议或 UDP 资格，不重做核心/证书/路由实现，不自动修改系统或云防火墙。

## 创建流程

1. 选用途，卡片展示完整连接方向。
2. 确认名称（可不填）、建议端口及已有证书。技术选项收进高级设置。
3. 成功后显示对应的主要交付按钮，原地复制或查看说明；失败保留输入并给明确中文原因。

两种默认用途都使用本机直接出口。新节点可以显式设置 direct，避免以后全局开关悄悄改变其出口。用途不是新路由模式：不将两个用途伪装成不同核心运行状态，也不通过 remark/tag/_vui 偷存用途造成未知字段或导出不兼容。若不新增存储字段，列表仅显示由真实配置/资格支持的连接操作，不声称记住了未持久化的用途标签。

推荐组合：sing-box / VLESS / 普通 TCP / TLS / 单用户 / 空 flow，复用现有后端凭据生成。当前 API 的 transport 字面值是 direct，不是 tcp 或 raw；后两者不能写进该核心的 profile。

建议端口采用现有默认值 10443；推荐向导限定 1024–65535，符合非特权节点服务配置，旧高级编辑与 API 范围保持。已被节点占用时即时说明，提交及应用仍须权威校验。不将数据库中未占用等同于操作系统端口空闲，更不等同于公网已放行。遇到其他服务占用，不停用其他服务、不抢端口。

已有正式证书按当前资格筛选：production、存在 revision、days_remaining 有限且不小于0、not_after 若提供必须晚于当前时间。唯一适用证书自动选，多张展示域名列表，读取失败可重试；没有证书时提供“先获取证书”入口。首次 CA 条款仍由管理员明确同意。SNI 与证书绑定保持现有后端校验。

## 当前接口的实际映射

下面为占位示例，不含真实会话、连接凭据或私钥：

```json
{
  "core": "sing-box",
  "protocol": "vless",
  "port": 10443,
  "remark": "",
  "routing_mode": "direct",
  "profile": {"security": "tls", "transport": "direct"},
  "certificate_id": "<所选证书ID>"
}
```

- POST /api/inbounds：创建；不传手工证书/私钥路径或自行拼原始核心配置。
- GET /api/subscription/link/{id}：明确点击普通分享后读取；URI 包含凭据，不写入 URL query、日志或持久浏览器存储。
- POST /api/subscription/upstream/{id}：另一台 V-UI 用途，传实际目标域名/IP、固定默认 uri 格式、acknowledge_tcp_only=true。生成动作前明确“内容含连接凭据、仅 TCP”，不能省略服务端用途确认或去掉资格校验。
- 其他客户端格式和下载留次级操作，不让新手先选择 URI/YAML/JSON。
- 中转页面继续用现有导入预览、保存、检查、应用和诊断；保留 If-Match、base_revision、idempotency-key、失败不回退 DIRECT 等协议，不伪装一键成功。

上游导出目标地址提供明确建议并可修正；不把 HTTPS 面板 URL（含协议/路径/管理端口）直接传作节点地址。保留节点自己的 TLS 名称及验证，连接地址不替代 SNI。

## 旧节点、资格与真实状态

旧节点不经过新建推荐配置自动转换。编辑只改用户明确修改的字段，保留核心、凭据、传输、手工材料/托管绑定、到期设置和原路由模式。继续携带 expected_instance_revision；409冲突要求刷新，不能覆盖新实例。

普通分享与供另一 V-UI 使用是不同导出资格。当前 tcp_upstream_profile 明确要求已启用、无到期配置、sing-box/VLESS、单用户、已支持 TCP TLS/REALITY 等约束。Xray 的普通 RAW/TCP TLS 分享支持不自动授予服务器上游导出资格。

列表的按钮必须由真实资格决定。新流程为相应用途选择推荐组合；旧不兼容节点不显示为“可用于另一台服务器”，也不静默删配置解锁导出。若现有公开摘要不足以判断资格，最小新增非敏感资格布尔字段，并增加 allowlist/负向检查；不为列表取回全部原始配置或凭据。

列表保留名称、端口、启用状态及必要运行/失败状态。日志、技术字段、原路由设置与危险操作收进“更多/高级”。服务已启动不显示为“公网可用”；外部连接未测、失败或未知分别表示，不用简化措辞冒充测试结果。
