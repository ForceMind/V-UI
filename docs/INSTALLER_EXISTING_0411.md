# v0.4.11 候选：已有安装与配置恢复

## 范围与状态

用户要求：已有安装先读取原配置，交互选择沿用升级、未完成续装或修改配置；保留数据。构建及真实安装验收只在 GitHub Actions，不做浏览器测试。

从 main `586d8a2dbd0be6d7ba8d5c5823df8fe9a1f73c95` 创建版本分支 `release/v0.4.11`。当前稳定套件及短入口默认仍为公开 v0.4.10；候选验证完成不等于已发布。v0.4.10 的特定发布例外不自动扩大到本版本，公开新版本及短入口切换须有对应授权。

## 可观察行为

- 短入口检测安装配置路径存在时不先询问域名；由摘要校验后的安装器在安装锁内验证 root 所有权、路径及 JSON，再显示原域名、邮箱、管理员、监听地址与端口。
- `ready: true` 显示沿用升级；`ready: false` 显示继续未完成安装。选择 0 或回车取消，原配置及数据不变。显式 `--upgrade` 可以直接沿用；有冲突参数时必须明确选修改，不能静默套用。
- 修改界面以原值为默认，回车保留；域名、邮箱、IP、端口逐项检查，显示变更并再次 y/n 确认。托管证书仍单独确认域名控制权、CA 条款及公开证书记录。
- 已有管理员账户、密码、节点和订阅保持。管理员改名使用已有面板账户功能；证书模式保留，不在此菜单切换 managed/provided。节点 TCP 端口仅作预检及防火墙声明，不批量改写已建入口。
- provided 模式沿用安装目录内材料；早期中断尚未保存材料时提示原文件路径。没有自动改为托管签发，不跳过 TLS 校验。

## 写入与恢复

已有安装先记录 root-only 停服恢复意图，停服备份后补充证书/运行指针快照，再启用候选和应用配置。持久记录位于 `/etc/v-ui/.install-transaction.json`，可能含原自带私钥材料，权限 0600；不可发布、删除或作为普通诊断输出。

配置事务只保存/恢复 root 配置、启动文件、服务模板、自带证书、原 panel binding、原证书邮箱及旧 CURRENT。helper 源码和完整 stdlib 控制器闭包来自同一校验包，仅降权至 v-ui 后执行，使用现有离线写入/数据/核心/证书 worker 锁。邮箱修改同步到托管证书记录及后续续签请求参数；不声称第三方已注册 CA 账户的资料已被远端改写。

失败或中止时先停止面板及 HTTP01，恢复上述状态，再恢复原先运行的服务并验证旧域名 HTTPS。系统信任根保留，provided 恢复还允许把 root 保护的原证书链作为验证锚；仍检查域名、签名和有效期。恢复失败保持停服及持久记录，下次正常运行安装器先重试恢复；dry-run 不做恢复或写安装锁。重复中止信号在恢复期间屏蔽；SIGKILL/断电依靠持久记录在下次运行时恢复，不声称能在进程已终止后后台自动运行。

不调用整个数据 restore，不删除数据库，不撤销原会话或订阅。旧安装没有 CURRENT 的早期断点允许保留新准备的版本指针供续装，不把不存在的旧版本称为已恢复。新证书历史及失败 jobs 保留，首次建库后失败只移除本次新增 panel binding，不删除新证书或业务行。

## 验收

独立只读审查已发现并修正：最早期无 unit 续装、preflight receipt 固定键集合、先停服后才记录恢复意图、dry-run 误恢复、具体 bind 地址健康检查、自带证书缺失、fullchain 不含根、helper 错误回显敏感 argv。源码与模拟不能替代真实安装。

定向单元覆盖原值继承/确认/取消、显式冲突、非法元数据、两阶段恢复、保留会话/订阅/节点、真实 SQLAlchemy 证书 schema，以及真实 helper + 临时 SQLite 结合安装器的健康失败/KeyboardInterrupt/SIGTERM/首次停服异常恢复。外部服务和健康失败在这些单元中模拟；不称真实 CA 签发或 systemd 验收。

准确候选 Actions 必须单独验证：完整普通测试、固定核心/回环与四目标构建；空白 systemd runner 真实安装和全局菜单；无重复填表的取消/升级；已有数据 ready:false 且 unit 缺失续装；邮箱/面板端口修改；占用端口拒绝；错误域名真实 TLS 失败后旧配置/已认证会话/代理草稿恢复；provided 原链不含根时的恢复。正式结果、提交及链接在本记录和承载 PR 更新，不预填绿灯。

当前未构建或安装本地 Linux 套件，未访问真实 VPS，未替实际域名同意 CA，浏览器未验证。
