## 已发布入口的问题

1. 旧 `cleanup_bootstrap` 以 `[[ -n "$BOOTSTRAP_RUNTIME_DIR" ]] && rm ...` 作为末条命令；目录变量为空时返回 1。在 `set -e` 与旧 EXIT 清理组合下，在线路径会覆盖原来成功的 0 或控制器原失败码（例如 7），让调用方误判结果。
2. 旧 `PYTHON="$(bootstrap_portable_python)"` 在命令替换子 shell 执行引导。子 shell 写入的临时目录变量不会回传父 shell，后续清理不知道目录归属。
3. 引导调用位于 `||` 条件上下文中，不能依赖 `set -e` 保证内部 curl、摘要校验或 tar 失败即停止。必须逐项显式检查，不能继续执行未完成验证的 runtime。
4. 本地路径原先用 `exec` 替换 shell，所需 EXIT 清理不会在安装控制器返回时执行；原清理注册时机也晚于便携引导分配。

遇到 v0.4.7 非零退出时，先保留完整输出，核对控制器错误、安装记录、活动版本和服务健康。非零不证明安装完全没有发生，也不能一律改成成功或用 `|| true` 掩盖。不要未经检查就重复安装，尤其不要删除数据、替换摘要或改用未验证的分支/旧包混合套件。

## 修复契约

- 在任何安装器自有临时目录分配前，初始化目录状态并注册统一 EXIT、INT、TERM 处理。清理先保存原退出码，处理完资源后按原状态退出。
- 空目录状态不产生新的错误。每个已登记的安装器自有临时目录都独立尝试清理；单个删除失败给出警告并继续，不覆盖控制器原状态。清理只针对本次创建的临时目录，不删除安装数据、活动 release 或用户提供的本地 kit。
- 便携引导函数在父 shell 调用，直接登记临时目录与 `PYTHON` 路径，不通过命令替换回传 runtime 路径。下载、固定 SHA-256 和解压分别显式拦截；任一步失败都不得运行提取出的 Python 或安装控制器。
- 本地和在线安装控制器正常返回后，由 shell 进入统一清理并保留其成功 0 或原失败状态。移除本地路径会绕开清理的 `exec`，但不改变控制器参数和安装权限。
- 处理临时目录分配与赋值之间的可捕获信号窗口：先记录待退出信号，取得非空目录路径后即登记归属，再处理分配失败或信号退出。即使 `mktemp` 因同一进程组信号返回非零，也不能丢掉它已输出的目录路径。INT/TERM 的状态分别为 130/143；Bash 可能等前台子进程返回后才执行 trap，因此不保证只向父 shell 发信号能立即打断长时间运行的子进程。本修复不是进程监督器，不提供即时取消保证。清理只能处理已捕获输出并登记的已知路径；若 `mktemp` 创建目录后、输出路径前被终止，父 shell 无法发现该未知目录。不声称可以处理 SIGKILL、断电、内核故障或保证失败的文件删除最终成功。
- 保留 curl 的 HTTPS 协议限制、重定向限制、TLS 最低版本、失败/超时选项，以及固定来源与摘要。修复不借由跳过校验、改 pin 或执行任意下载列表中的路径实现。

## 回归与验收边界

新增 shell 行为回归使用真实 Bash 进程、临时目录和受控假工具；覆盖范围应包括：

- 在线入口和两种本地控制器布局的成功/失败状态传播，包括 0 与 7
- 系统 Python 与便携引导分支的临时目录归属及清理；同时存在两个目录时各自清理
- 下载、摘要与解压失败后禁止执行 runtime/安装控制器
- 空目录、清理失败、可捕获 INT/TERM 以及目录分配/赋值窗口
- 失败时保持原状态，保留 HTTPS/pin/固定文件名等信任边界

这些测试是 shell 行为回归，不是网络下载、真实 root/systemd 安装、四平台真实包消费或生产部署验收。假工具结果不能补发真实安装资格；SIGKILL/断电后的遗留资源不在可捕获信号清理保证内。普通单测、真实核心、浏览器、安装/systemd、制品来源和公开发布必须分开记录。
