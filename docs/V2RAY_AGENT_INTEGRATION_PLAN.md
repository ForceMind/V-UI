保留 Python/FastAPI/SQLite、Certbot、核心适配器、权限与配置事务，参考上游流程和失败场景，在 V-UI 对应模块实现。V-UI 继续统一管理运行配置，上游 Shell 不作为第二个配置管理者，也不整仓导入。实际源码复用须记录来源并核对许可证；V-UI 自有代码为 MIT，上游为 [AGPL-3.0](https://github.com/mack-a/v2ray-agent/blob/b407b5e56832c5a5efcd9c73921dface72eff987/LICENSE)。

## W0 当前状态与文档校准

核对 README、兼容矩阵、安装、运维、开发交接及 AGENTS 的事实，明确已发布 v0.4.26、已交付 P2/P3/P4、限定 XHTTP、受阻 D2、Tailscale 只读状态和部署边界。旧全文和原始失败保留固定提交链接。

完成标准：用户入口不再同时以“当前”描述冲突版本；支持声明能追到精确协议范围与证据；文档整理不变更 VERSION、发布资产、权限或测试政策。

## W1 能力与诊断一致性

优先复用 `protocol_profiles`、`inbound_export_eligibility`、`xhttp_profile`、`core_updates` 与现有管理器观察。前端不另建可绕过服务端的资格白名单，未知组合仍明确拒绝。

首个实现块集中在核心身份：保留 `/api/proxy/capabilities` 现有兼容字段；另外区分内置兼容基线、已选组件与有身份验证依据的实际运行核心。选择记录不冒充运行事实，停止、身份不明或观察失败应有明确状态。只读聚合不触发核心启动、更新、候选下载或配置写入，不输出凭据、完整配置、材料路径和原始异常。

后续诊断子项分层呈现 DNS A/AAAA、监听、主机防火墙、TLS、核心与实际请求。缺少外部证据时保留“公网可达性未验证”。UFW/firewalld 放行仍逐条展示并等待明确确认，不擅改 SSH、云安全组、自定义规则或无关服务。首块完成不能记为全部环境诊断完成。

完成标准：旧 API 消费者兼容；界面正确区分基线、选择和运行版本；正常、停止、未知、权限和身份失效路径有针对性回归；节点/API/导出继续使用既有资格判断。

## W2 Cloudflare DNS-01 首装与恢复

在现有首装中增加 DNS-01，统一提供 HTTP-01、Cloudflare DNS-01、已有证书三条选择。复用 `scripts/install_system.py`、`app/certificates/cli.py`、证书 manager、DNS 凭据和 journal，避免新增未鉴权的网页密钥入口。

- HTTP-01 保持既有域名、TCP 80 与 CA 条款要求。端口冲突给出选择，不停止无关服务。
- DNS-01 从可信终端隐藏输入受限 Token，通过私有管道交给服务用户的证书 CLI；秘密不进入 argv、环境、URL 或日志。Zone 读取成功仅是预检，不代表写权限。
- DNS-01 和已有证书首装均不因 80 端口占用失败，也不无条件启动 HTTP responder。以后申请 HTTP 证书时须明确建立所需服务和端口条件。
- 已有证书校验域名、证书链、私钥匹配和有效期，保留手工或托管身份；首装不额外申请 ACME。先确认 HTTPS 就绪，再交付管理员凭据。
- 已写入或结果未知的 TXT 必须保留凭据修订、准确归属和清理上下文。进程被终止或本地安装回退不能抹掉远端副作用；未知写入先核对，不重复发起。
- 先核查 DNS 传播与子进程时限、全局写锁与 DNS 锁顺序、DNS-only 安装后的 HTTP responder 启用路径，以及备份和旧 reader 能力门槛。

完成标准：80 占用时两条非 HTTP 路径成功；错误 Token、无写权限、传播超时、未知写入、启动失败和进程中断可恢复；旧 HTTP 首装和已有 DNS 绑定升级通过。假凭据/临时 CA 自动化、真实 Cloudflare 签发与续期分别取证。**申请、清理与恢复同批交付，不能只发布成功路径。**

## W3 客户端交付与订阅体验

复用 `client_export`、`validated_export`、`subscription_tokens` 和 `mihomo_routing`，统一“选择客户端 → 选择节点与客户端服务规则 → 预览 → 获取订阅或二维码 → 验证连接”。

Mihomo YAML 包含合资格节点、策略组、规则及 DNS；URI/Base64 主要是连接信息；sing-box JSON 仅提供已验证组合。当前 XHTTP 不具备 sing-box JSON 资格，混合授权请求该格式时整单拒绝，不能静默丢节点。

普通升级与界面调整保持原订阅 URL、节点 UUID/密码、期限和撤销状态。撤销订阅阻止继续下载，不自动使已下载节点凭据失效；每设备独立凭据另行设计。默认本机配置检查回环监听，LAN 分享和控制接口开放须显式选择并保持认证。

服务器 YAML 改变服务器执行规则；ToClash 规则改变客户端下载的配置。两者分别标明作用域，不自动同步。服务器规则应用不依赖客户端刷新订阅才生效；客户端规则保存后刷新原订阅取得新版本。

完成标准：授权下载后固定真实客户端能解析并实际转发，错误 TLS/凭据被拒绝，原 URL 可取得最新已保存规则；正常升级与备份恢复各自遵守原授权合同。

## W4 静态规则与恢复增强

复用 `proxy_store`、`proxy_apply`、`proxy_recovery` 和 `mihomo_merge_plan`。普通单上游与静态 YAML 模式继续明确区分；本批只增强已支持语义，不加入动态 provider、嵌套组或任意规则执行。

应用前检查重名、失效引用、循环、完全遮蔽、顺序和末尾默认出口变化。无法证明等价时让用户明确选择，不自动重排。预览受影响入口、服务、DNS 路径和出口；检查绑定工作区 revision、来源材料、地址快照和运行身份，相关变化均须重新检查。

沿用持久事务和幂等请求，在配置切换、启动、健康确认和恢复阶段注入中断。多文件逐个替换或 Shell trap 不能单独证明完整恢复。受保护路由按明确失败策略处理，不能隐式 DIRECT；结果未知读取原任务，不重复写入。

完成标准：真实流量符合规则顺序和预览；失败及中断不走意外出口，保留旧可用配置、凭据、停止意图和历史记录，不能确认恢复时显示待恢复。

开始前核对 main/dev 与未提交内容，正常同步主线；任务分支从 dev 建立，版本候选从 dev 建 release 分支。只提交本任务文件，独审及必要检查完成后按对应授权正常 PR 集成，不强推或改写共享历史。发布仅晋升准确提交已验制品，不重建或覆盖旧资产。

## 兼容迁移与验收

正常升级保留账号、数据库、节点、有效订阅、已应用证书和私有材料；备份恢复继续撤销旧管理会话、订阅令牌及维护授权，DNS profile 恢复后待验证，旧任务不自动重放。旧安装缺少新增挑战字段时按已有语义处理，已安装实例以实际已应用绑定为准，不能把待应用材料升级为已应用。

新数据能力门槛必须由回退目标理解；不能删除字段、能力声明或 journal 来绕过旧 reader。恢复涵盖配置、启停意图和任务状态，DNS 远端副作用按准确归属处理。

| 验收层 | 本轮需要的证据 |
| --- | --- |
| 文档/源码 | 当前版本和边界一致、链接有效、无敏感输出、差异独立审查 |
| API/合成 | 旧字段兼容，选择与运行身份分离，权限/停止/未知状态正确；DNS 正负路径与中断恢复 |
| 真实安装 | 空白 Actions 主机验证 HTTP、DNS、已有证书、80 占用、升级和失败恢复 |
| 真实核心/客户端 | 实际配置解析、TLS/凭据正负例、出口与规则顺序，失败不意外直连 |
| 浏览器 | 按具体场景授权后单独验证；当前不运行，未验证状态保留 |
| 外部环境 | 真实 Cloudflare、手机公网、低配完整服务组及至少 24 小时分别取证 |

构建与系统安装遵守仓库的 Actions 限定，真实账号、主机、网络及凭据操作另核授权。缺少某层证据时准确列为待验，不能用普通 CI 成功或公开 Release 代替。

## 后续扩展进入条件

- **多出口与多服务器：** 先完善已有加密 TCP 链路上的静态显式出口选择，确认真实出口、DNS 和断链行为；自动切换另定触发与恢复条件。多机注册、授权、采集和任务恢复需要独立控制协议。
- **远程订阅聚合：** 输入下载与当前输出分享分开；先定义来源、命名空间、HTTP/重定向、内网与元数据地址限制、大小/时限和失败保留上一版策略。
- **Docker/PWA：** 容器单独验证固定镜像、持久化、网络、升级与恢复。PWA 优先移动页面和安装能力，管理 API、订阅、秘密与私有响应不进入离线缓存。
- **新协议/UDP：** 逐项建立核心与客户端矩阵。D2 先解决逐报文目标限制、大包、原关联空闲释放和背压失败，产品中转 UDP 维持关闭。Go/Rust 后端重写仍暂缓。
