# alpha.6 — 已保存分流与专用订阅闭环

依赖已验证 alpha.5 / 698d098。入口 `/workspace`，账户页及旧面板的分流/订阅导航都可进入。页面只请求本机 API，不引入新的前端依赖。

## 操作

1. 在节点管理准备已验证的 sing-box VLESS/TCP/TLS 节点（单用户、空 flow、启用证书校验）。
2. 在分流设置中选择常规/默认直连、40 项 ToClash 预设、自定义直连/代理、CGNAT 与多个内网 DNS 区域。
3. “预览草稿”不会写磁盘或影响订阅。“保存设置”使用读取时的修订号提交；冲突时必须手动重新载入，不自动覆盖其他页面的修改。
4. 在订阅表单填写独立的节点连接地址、选择明确节点和输出格式，创建专用只读令牌。
5. 新地址仅本次显示，可复制或下载 Mihomo YAML。遗失时轮换；撤销/过期/管理员改密后原链接失效。
6. 规则保存后仍使用同一个订阅 URL，客户端需要刷新。未保存草稿不会改变导出结果。

### 重新载入时保留新输入（2026-10-21 独立修正）

“重新载入”只在设置与已保存预览都成功读取、且请求期间没有新的表单编辑时，才一起替换表单、保存基线和修订号。已有草稿仍先询问是否放弃；取消不发请求。确认仅针对点击时的草稿，不授权覆盖等待响应期间的新输入，即使后来又改回原值也不采用这次旧响应。发生新编辑时保留表单与原 If-Match 修订，提示用户再次载入；不假报新草稿已保存，也不自动重试保存冲突。

读取设置或预览失败时，既有表单、保存基线、修订号和预览内容均保持；错误提示不代表载入成功。等待请求时输入仍可编辑，按钮仍沿用既有 busy 互斥。这里的同步提交仅指页面 UI 状态，不是服务端两个 GET 的事务快照；其他页面在两次读取之间保存时，设置与预览可能来自不同保存版本，这一既有一致性边界没有改变。保存、草稿预览、订阅及后端持久化契约不变。

`node tests/workspace_reload_dom.js` 直接执行产品脚本，以 24 项确定性 DOM/fetch 控制覆盖两阶段竞态、确认/取消、HTTP/JSON/network 失败、保存修订与原预览保护。独立审查追加的 6 项分别在 snapshot / preview 阶段验证 JSON 解析期间编辑、编辑后改回原值、以及新编辑后请求失败；由 `test_workspace_controller.py` 接入普通 unittest 并严格核对 24 项全通过、零 skip。它不等于实际浏览器验收。既有 `VUI_WORKSPACE_BROWSER=1` 工作流另加入延迟真实本机 API 响应的四组场景（snapshot / preview × 初始干净 / 已确认放弃旧草稿），核新输入、未保存状态、原 If-Match 和显式保存结果，不伪造成功响应。当前开发云端已有 Chromium EPERM 限制，本次未重新启动浏览器；新候选与合并后准确提交的实际 Chromium、完整 CI 和独立审查仍须各自验证，不能继承下方旧 alpha.6 结果。未发布或部署。

## 持久化

使用既有 `mihomo-routing.json`，不改变 ToClash 规则规划器。加载经过 alpha.5 严格校验；文件损坏返回明确错误，不能静默回到默认分流。

写入使用进程文件锁、If-Match 修订条件、独立临时文件、fsync 和原子替换。无效输入、修订冲突或原子替换前失败保留旧文件；无法确认磁盘写入时提示重新读取修订，不假报成功。旧格式合法 JSON 可以直接读取，第一次成功保存后规范化。

GET `/api/routing/mihomo` 保留原设置响应，新增 ETag；PUT 要求 If-Match，否则 428。新增 `/snapshot` 供 UI 获取设置/修订；POST `/preview` 仅预览草稿，GET `/preview` 展示已保存版本。旧分流/订阅导航转入同一个工作区，不再运行原来的无修订写入流程。

令牌管理沿用 alpha.3；新增创建前的已验证导出检查，避免直接生成已知不可用的订阅。订阅列表只展示范围/有效期/失效状态，不回显令牌。订阅、生成 YAML 和草稿不写入 Web Storage；不向外部转换服务发送节点。
