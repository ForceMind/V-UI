# alpha.6 — 已保存分流与专用订阅闭环

依赖已验证 alpha.5 / 698d098。入口 `/workspace`，账户页及旧面板的分流/订阅导航都可进入。页面只请求本机 API，不引入新的前端依赖。

## 操作

1. 在节点管理准备已验证的 sing-box VLESS/TCP/TLS 节点（单用户、空 flow、启用证书校验）。
2. 在分流设置中选择常规/默认直连、40 项 ToClash 预设、自定义直连/代理、CGNAT 与多个内网 DNS 区域。
3. “预览草稿”不会写磁盘或影响订阅。“保存设置”使用读取时的修订号提交；冲突时必须手动重新载入，不自动覆盖其他页面的修改。
4. 在订阅表单填写独立的节点连接地址、选择明确节点和输出格式，创建专用只读令牌。
5. 新地址仅本次显示，可复制或下载 Mihomo YAML。遗失时轮换；撤销/过期/管理员改密后原链接失效。
6. 规则保存后仍使用同一个订阅 URL，客户端需要刷新。未保存草稿不会改变导出结果。

### 创建前确认节点实例（2026-10-23 独立修正候选）

新版工作区将显示时读取的实例集合修订随每次创建提交。其他页面删除/重建节点后，即使整数 ID 复用，旧页面创建也明确冲突，不会把原选择悄悄授权给新实例。点击“刷新节点和订阅”会清空旧节点勾选，读取成功后请重新选择；刷新失败或修订不可确认时阻止创建。分流草稿及其 If-Match 独立保留，原令牌轮换/撤销/Hide 生命周期不变。

同实例合法编辑不等于更换实例；未选中节点的新增/删除也会使全库存修订变化。升级前已加载的旧页面和主动省略条件的普通 API 不受此新版 UI 保护，升级后须重新加载。服务端条件是原子并发保护，不替代节点身份授权或导出校验。完整[新授权契约](SUBSCRIPTION_IDENTITY.md#2026-10-23-新授权的陈旧页面选择保护候选)说明兼容、恢复与分层验收；未发布或操作真实用户数据。

### 重新载入时保留新输入（2026-10-21 独立修正）

“重新载入”只在设置与已保存预览都成功读取、且请求期间没有新的表单编辑时，才一起替换表单、保存基线和修订号。已有草稿仍先询问是否放弃；取消不发请求。确认仅针对点击时的草稿，不授权覆盖等待响应期间的新输入，即使后来又改回原值也不采用这次旧响应。发生新编辑时保留表单与原 If-Match 修订，提示用户再次载入；不假报新草稿已保存，也不自动重试保存冲突。

读取设置或预览失败时，既有表单、保存基线、修订号和预览内容均保持；错误提示不代表载入成功。等待请求时输入仍可编辑，按钮仍沿用既有 busy 互斥。这里的同步提交仅指页面 UI 状态，不是服务端两个 GET 的事务快照；其他页面在两次读取之间保存时，设置与预览可能来自不同保存版本，这一既有一致性边界没有改变。保存、草稿预览、订阅及后端持久化契约不变。

`node tests/workspace_reload_dom.js` 直接执行产品脚本，以 24 项确定性 DOM/fetch 控制覆盖两阶段竞态、确认/取消、HTTP/JSON/network 失败、保存修订与原预览保护。独立审查追加的 6 项分别在 snapshot / preview 阶段验证 JSON 解析期间编辑、编辑后改回原值、以及新编辑后请求失败；由 `test_workspace_controller.py` 接入普通 unittest 并严格核对 24 项全通过、零 skip。它不等于实际浏览器验收。既有 `VUI_WORKSPACE_BROWSER=1` 工作流另加入延迟真实本机 API 响应的四组场景（snapshot / preview × 初始干净 / 已确认放弃旧草稿），核新输入、未保存状态、原 If-Match 和显式保存结果，不伪造成功响应。当前开发云端已有 Chromium EPERM 限制，本次未重新启动浏览器；新候选与合并后准确提交的实际 Chromium、完整 CI 和独立审查仍须各自验证，不能继承下方旧 alpha.6 结果。未发布或部署。

## 2026-10-24 已保存预览版本核对候选

上文 2026-10-21 保留的跨 GET 混版边界是本次独立修复对象，不改写原历史。已保存预览接口原本就返回 revision；新版页面只在它与此次 snapshot 或已确认 PUT 的修订严格匹配时显示对应预览。缺失、畸形或不同的修订不被当成匹配，也不自动重试或悄悄接受另一写入者的版本。

- 重新载入时，设置与预览不一致会保持原表单、保存基线、If-Match 和预览；原来的放弃草稿确认不授权接受混版。初次载入失败时工作区仍隐藏，提示也说明可刷新页面，而不是只引导点击不可见按钮。
- SAVE 已确认后出现预览版本不一致，不代表刚才的保存失败或回滚。已确认的修订 / 保存基线保留，请求期间的新输入仍是未保存草稿；不显示另一版本的规则作为本次保存结果。用户可明确重新载入，后续仍遵守原确认及 If-Match 冲突处理。
- 同版本核对不是跨请求服务端事务，也不承诺读取后不会有其他写入者再保存。规则、后端 API、落盘与客户端订阅协议不变。

隔离审计使用真实路由函数 / ETag / 临时存储与受控 DOM/fetch，不能称 HTTP 或实际浏览器资格。新增真实 Chromium 场景仍通过既有一次性认证服务、正常按钮和真实第二写入者检查，须在准确候选 CI 执行；本地未尝试既知受限的原生执行。候选、合并主线及四目标门槛独立，不操作用户数据库或真实网络，不发布部署。

完整备份保留身份/绑定，但恢复仍撤销会话和全部旧订阅访问；不自动复活 URL。迁移、损坏拒绝、旧 reader 回退风险和隔离测试边界见[节点实例绑定契约](SUBSCRIPTION_IDENTITY.md)。此为独立开发候选，尚未迁移实际用户数据库、发布或部署，不能继承旧 alpha.6 或其他 PR 的验收。

## 2026-10-22 新地址的本地生命周期修正候选

### 实际问题与最小合同

创建或轮换先显示新 bearer URL，再等待订阅列表刷新。旧控制器在整个操作期间禁用“隐藏地址”，所以列表请求滞留时，已经可见的地址不能通过正常按钮点击隐藏。此次只让本地“隐藏地址”保持可用，其余写入/复制/下载仍遵守 busy 互斥；没有缩短超时来掩盖等待。

每次隐藏都会推进独立的新地址代次，清空页面 URL 与当前引用并隐藏区域；既有 pagehide 与 HTTP 401 清理也走同一路径。创建/轮换在清除旧内容之后记录自己的代次，只有代次仍匹配才显示新结果或提示保存新地址。隐藏不会取消或撤销已经授权的服务端创建/轮换；原请求仍只发送一次，完成后可刷新非敏感的授权列表，不自动重试、撤销或另发轮换。隐藏后需要找回地址时，仍由用户明确决定是否轮换。

下载分别在 fetch 与 blob 两个 await 之后核对代次，失效后不再读取尚未消费的正文、不创建 object URL 或点击下载链接。复制已调用 clipboard.writeText 后不能召回；代次失效只阻止迟到的“已复制”提示，以及失败后的 focus/select 和手动复制提示。已经启动的下载也不能撤回。这里清理的是可见内容与控制器当前引用，不声称擦除浏览器内存、剪贴板或磁盘上的既有数据。

没有改变后端 API、令牌有效期、轮换确认、If-Match、节点实例绑定/失效状态、明文 DOM 处理或不写 Web Storage 的约束；不增加依赖、API、自动请求重试或实际账号操作。

## 2026-10-22 保存确认与恢复回归覆盖

这是已有保存行为的五项回归覆盖，不是产品缺陷修正，也不将先前审计的重复控制计作新缺口：

1. 实际验证返回 422 时，磁盘字节、原修订和脏草稿不变；纠正草稿后仍用原 If-Match 保存成功。
2. 第二写入者实际提交后，本地旧修订得到 409，保留服务端赢家与本地草稿，不自动重试或采纳赢家修订；明确重新载入后才用该修订保存下一草稿。
3. 实际落盘但成功确认正文不可解析时，UI 保持原保存基线/修订和脏草稿；重试实际冲突，明确重新载入完成恢复。模拟的是确认丢失的一种形式，不声称覆盖全部网络故障。
4. PUT 已确认而随后已保存预览读取失败时，新保存基线与修订保留，旧预览不替换，并显示错误；不能假回滚或假报预览成功，下一次保存使用已确认修订。
5. 已确认保存之后、预览等待期间的新编辑保持脏草稿及 beforeunload 保护；旧预览被抑制，下一次保存使用已确认修订。

`test_workspace_save_recovery.py` 使用运行 unittest 的 Python 解释器启动 Node 控制，并严格核对恰好 5 项、全部通过、零失败/取消/skip/todo，整个子进程有 90 秒硬上限。每个场景只有一个 Python 子进程（15 秒上限），JSON-lines 通信有界；生产模块只导入一次，真实模型/路由函数/ETag/HTTPException/校验/规则规划与磁盘写入共用独立 TemporaryDirectory。每场景显式关闭子进程并核对临时目录清理，使用确定性 await gate，不启动 HTTP 服务、监听端口、浏览器或真实核心。原重载 24 项用例正文不变，仅抽取共享 DOM 夹具；新地址 40 项及实例状态 35 项控制原文件不变。

这些是受控 DOM/fetch 与实际后端直接函数/临时存储的组合证据，不是 HTTP 请求栈、认证、原生表单校验、真实导航/bfcache 或 Chromium 验收。实际产品脚本和后端字节保持不变；准确新候选与主线仍各自完成独审、普通套件、完整 CI 和四目标，不能继承旧主线资格。完成本有界覆盖后停止扩展测试，剩余真实环境、发布与部署计划另行列明。

## 持久化

使用既有 `mihomo-routing.json`，不改变 ToClash 规则规划器。加载经过 alpha.5 严格校验；文件损坏返回明确错误，不能静默回到默认分流。

写入使用进程文件锁、If-Match 修订条件、独立临时文件、fsync 和原子替换。无效输入、修订冲突或原子替换前失败保留旧文件；无法确认磁盘写入时提示重新读取修订，不假报成功。旧格式合法 JSON 可以直接读取，第一次成功保存后规范化。

GET `/api/routing/mihomo` 保留原设置响应，新增 ETag；PUT 要求 If-Match，否则 428。新增 `/snapshot` 供 UI 获取设置/修订；POST `/preview` 仅预览草稿，GET `/preview` 展示已保存版本。旧分流/订阅导航转入同一个工作区，不再运行原来的无修订写入流程。

令牌管理沿用 alpha.3；新增创建前的已验证导出检查，避免直接生成已知不可用的订阅。订阅列表只展示范围/有效期/失效状态，不回显令牌。订阅、生成 YAML 和草稿不写入 Web Storage；不向外部转换服务发送节点。
