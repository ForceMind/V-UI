# DNS-01 首次安装与 HTTP 服务选择

本页记录 [Issue 175](https://github.com/ForceMind/V-UI/issues/175) 的 W2 候选实现。公开 v0.4.26 不包含本页新增的安装参数；只有从该功能提交构建并校验的候选套件才可使用。发布状态、源码提交和安装验收分别核对，不把候选操作说明当成稳定版交付记录。

## 三种证书方式

| 方式 | 首次安装输入 | 默认启动 HTTP-01 服务 | 80 端口 |
| --- | --- | --- | --- |
| HTTP-01 | 面板域名、联系邮箱、明确同意 CA 条款 | 是 | 检查端口并按既有规则处理防火墙 |
| Cloudflare DNS-01 | 上述输入、域名所在区域、隐藏输入的 API Token | 否 | 不作为该安装方式的证书验证要求 |
| 自备证书 | 证书链与配套私钥路径 | 否 | 不作为该安装方式的证书验证要求 |

交互安装先选择证书方式。HTTP-01 保持原有默认。DNS-01 复用现有 Cloudflare 凭据、证书任务和 TXT 清理记录；本批面板首装仍使用明确的面板域名，不自动创建通配符证书或 DNS 解析记录。

候选套件的校验和启动方式沿用[本地完整套件](INSTALLATION.md#3-本地完整套件)。准备好该页的安装函数后，可使用以下参数形式；示例中的域名、邮箱和路径须换成自己的值。

```sh
run_vui_local_installer \
  --domain panel.example.com --email admin@example.com \
  --certificate-method dns-01 --dns-zone example.com \
  --accept-terms
```

Token 随后从当前可信终端隐藏读取。命令行、环境变量、临时凭据文件和安装日志均不接收 Token。没有可信终端时拒绝读取，不回退为明文提示。区域的只读查询成功只证明区域可见，不能证明具有写入 TXT 的权限。

自备证书可继续使用原有参数，不必另外指定方式：

```sh
run_vui_local_installer \
  --domain panel.example.com --email admin@example.com \
  --cert /absolute/path/fullchain.pem --key /absolute/path/privkey.pem
```

域名、证书和密钥必须满足既有加载与 HTTPS 验证规则。自备证书不因此获得自动续期。安装仍在 HTTPS 就绪后才交付管理员账户；服务管理器显示运行不能代替该检查。

## HTTP-01 的显式选择

DNS-01 和自备证书安装仍注册受管 HTTP 服务单元，但默认不启用或启动它们。如果还需要 V-UI 为后续 HTTP-01 证书提供响应，可在候选安装或升级时明确传入 `--enable-http01`；这会检查 80 端口，并按既有授权规则处理本机端口。

安装配置使用严格布尔值 `http01_enabled`。旧安装缺少该字段时保持原行为，即视为启用；不会借普通升级关闭原 HTTP 服务。已有新配置的选择在普通升级中保留，升级不会自动切换证书方式或扩大 DNS 凭据权限。

维护菜单“启动”尊重该选择；“重启”、备份、恢复和候选激活仍恢复操作开始时的真实服务快照。操作开始前已停止的服务不因维护而自动启动。关闭 HTTP-01 的网络诊断会明确显示未启用，并继续分别报告面板端口、本机 TLS 与未知的公网入站状态。

## 独占引导与失败保留

首次 DNS 签发在停机写入事务中执行。引导进程、固定 Certbot 包装进程以及两个固定 DNS hook 持有同一个独占文件描述符；父进程退出不使仍存活的子进程失去排他性。该描述符只通过受控子进程继承，不进入环境变量或公开接口。

Certbot 包装适配仅接受现有提供器生成的两个固定 hook 调用，并绑定当前固定依赖版本。不会执行用户提供的 Shell 命令，也不把普通运行期的共享读写锁替换成首装独占锁。

安装回退保留原 DNS 凭据修订、证书任务、远端 TXT 意图和清理记录。远端写入超时可能代表已写入，也可能未写入；一次列表查询为空不能自动证明没有远端变更。本地程序或服务回退成功不能被报告为远端 TXT 已清理。

已有、有效且已经应用的 DNS 面板证书在普通升级时直接复用：不读取 Token，不重新签发，不把待应用的新修订提升为活动证书，也不清除原绑定错误。无人值守升级不会借此创建新的 DNS 凭据。

## 首装失败时的本机恢复

权限不足或未知远端写入可能发生在管理员交付之前。此时不能依赖尚未可登录的网页来修复。候选安装器提供 `--recover-dns`，只允许未完成的 DNS 首装，并由证书命令再次核对当前域名的未绑定证书记录。

若区域只读查询就已失败、尚未保存凭据和证书记录，直接重跑原安装会再次隐藏询问 Token；此时没有可恢复的记录，不使用 `--recover-dns`。恢复动作成功也不等于安装已经完成，仍需后续签发及 HTTPS 就绪检查。

通常首次失败会保留 `ready: false` 的安装配置。使用同一份已经校验的候选套件继续：

```sh
run_vui_local_installer --upgrade --recover-dns
```

若安装配置尚不存在，需要使用原来的完整 DNS 首装参数加上 `--recover-dns`；服务端仍须找到匹配的未绑定记录，不会凭此参数创建任意恢复目标。不要手工删除配置、面板绑定或 TXT 日志来取得恢复资格。完整安装、已有面板绑定和无人值守升级均不开放该入口。

恢复在可信本机终端显示所属区域、凭据状态及待处理任务，提供四个固定动作：

| 动作 | 实际效果与限制 |
| --- | --- |
| 替换 Token | 隐藏读取新 Token，核对同一 DNS 区域，按凭据修订更新；旧凭据版本和所有清理记录保留。 |
| 明确启用凭据 | 重新授权当前禁用或恢复后冻结的 profile，沿用现有凭据启用规则。 |
| 重试原 TXT 清理 | 选择显示列表中的完整任务 ID，按凭据与任务修订明确授权当前凭据处理原记录，再调用原清理逻辑。 |
| 人工核对 TXT 不存在 | 操作者先核对远端状态，再选择原任务并确认；仍由当前凭据执行查询，结果记为 `manual_confirmed`，不改写成自动 `cleaned`。 |

每次只选择一个恢复动作，并明确输入 `yes`。确认同时表示继续原安装；每次执行前重新核对凭据或任务修订，并按该修订提交，不接受过期状态。新 Token 不自动取得历史任务的清理授权。

签发冷却时间仍生效。若恢复动作已经保存，而继续签发被冷却阻止，安装回退保留新的凭据和清理结果；冷却结束后使用普通续装参数重试，不必重复已经完成的恢复动作。仍有待处理任务时再进入该恢复入口处理下一项。

## 验证边界

本批需要分别记录以下证据：

- 本地回归：私有 stdin 协议、隐藏终端、真实进程的描述符继承、权限失败、未知写入、超时与中断后的材料保留。
- ACME 验收：固定 Certbot、Pebble 与假 Cloudflare 的 DNS 签发及清理契约，并单独验证本批继承独占描述符的首装链路。既有 shared 路径的通过记录不能替代新增 EX 路径的结果。
- Actions 空白系统验收：候选套件构建、占用 80 时的 DNS 预检、自备证书默认安装、HTTPS 就绪、菜单启停，以及旧版升级配置保留。

DNS 安装预检通过不等于完整 DNS 首装签发通过；自备证书的真实系统安装也不替代 DNS 端到端验收。真实 Cloudflare 账号、用户域名、生产安装和浏览器需要各自的独立证据。
