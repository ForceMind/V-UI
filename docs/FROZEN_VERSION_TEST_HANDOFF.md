## 2. 安装材料核对（运行管理员命令之前）

- 想安装旧正式版：只按[固定版本安装指南](INSTALLATION.md)准备完整 19 项资产、可信来源与摘要、root 私有副本，再由操作者明确执行安装。`install.sh --version v0.4.8` 实际读取 `releases/download/v0.4.8`，**不是 master 或当前源码目录**。不要改成虚构版本、提交 SHA 或 `latest`。
- 想测试 f01dbd82 新功能：需要准确该提交的已验完整候选材料，不能把旧 v0.4.8 包配上新分支安装脚本。现阶段没有在本页提供或重新核验候选下载地址；没有拿到可验证材料就先停在材料准备，不用旧包冒充新功能。
- `RELEASE.json` 的 `source_commit`、各目标包内 `MANIFEST.json` 的 `source_commit` 必须与选定完整 SHA 相同；同时核对 `release_id`、`version`、目标架构 / libc 及完整 SHA256SUMS。摘要验证不替代来源信任，GitHub 自动 Source code ZIP 也不替代项目的 `vui-source.zip`。
- 单目标 Actions kit 与正式聚合的四目标 19 项资产不是同一种集合。候选附件过期、缺失、摘要不符或来源不一致时停止，按[发布门槛](RELEASING.md)重新取得准确材料，不拼装历史附件。
- YAML CLI 是**源码环境工具**：`scripts/preview_mihomo.py` 不在 portable 运行包的脚本白名单中。不要在已安装目录假定存在 `.venv` 或这份 CLI；面板 API 的 `app/` worker 和 `web/` 资源属于打包范围，但源码静态检查不替代包内执行验收。

## 3. 操作者安装前检查

- 使用自己有权管理的测试主机；确认 CPU / libc / init、域名、证书及端口。默认面板 TCP 8443、HTTP-01 TCP 80、节点 TCP 10443；端口占用不能靠结束原网站或改变 SSH 解决。
- 已有实例先按[运维指南](OPERATIONS.md)保存离机备份与原启动锚点；代码回退不等于数据恢复。不要删数据库或盲目反复安装来掩盖问题。
- 不关闭证书验证，不默认传入 `--assume-external-ports-open`；只有操作者确已核对规则才可作该声明。域名 / 邮箱 / CA 条款、任何防火墙变更均由操作者自己确认。
- 外层安装 shell 即使传 `--dry-run` 仍可能下载或安装引导工具，不能当作零写入检查。完整步骤见[安装指南](INSTALLATION.md)，这里不提供另一套相互冲突的一键命令。

## 5. 可选 YAML 面板：仅在取得对应可测试候选后

这不是当前旧正式包或 f01 基线应出现的功能。先核准确来源，再用无秘密的合成输入：

```yaml
rules:
  - MATCH,DIRECT
  - MATCH,REJECT
```

- 在 `/proxy` 打开只读预览，点击生成前不得请求解析；点击后输入发送给当前面板服务器，不是浏览器内离线解析。
- 可选基线留空；应出现固定冲突 / MATCH 后规则诊断和“不可应用”，不能提供应用按钮或改变运行配置。
- 分别检查 UTF-8 文件、编辑后旧结果失效、清空、关闭 / 重开、退出会话后的敏感显示清理。不要使用真实凭据复现界面问题。
- Node 合成 DOM 覆盖不等于原生浏览器结果；真实浏览器专项仍待对应新准确候选执行。详见[面板合同](MIHOMO_PANEL_PREVIEW_CONTRACT.md)。
