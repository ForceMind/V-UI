# YAML 路由计划应用契约草案

本契约承接 ROADMAP 的 P4。私有合并、冲突选择、下载与静态规则已经进入草稿 PR #147。本文定义把该计划接到现有受管服务的必要边界，运行应用尚待实现。

## 用户操作与作用范围

用户提供两份 YAML、逐项解决冲突，再为每个被引用的静态 select 分组选择成员。应用页面展示基于当前工作区的检查结果，用户明确确认后提交。检查和应用均须管理员登录，下载授权不作为应用授权。远程维护若要应用 YAML，需要另行明确委托该用途。

第三版文档增加显式执行模式，原单上游模式完整保留。用户切换到 YAML 模式后，YAML 规则作用于现有每入口策略选中的受保护来源。它与本机程序代理和入口中转两个开关共同决定实际来源，本机代理仍只监听回环并要求认证。原入口的 direct、inherit、relay 语义仍由原策略计算。启用但不支持整体中转的入口继续拒绝提交，另一核心的运行门槛仍由 CoreManager 核验。

DIRECT 是 YAML 明确选中的出口。所有受保护来源仍受自机地址、上游地址及非公网目标阻断约束。运行时既不能因缺失组成员、上游失效或未知字段而绕过规则，也不能在失败时提交部分配置。

## 规则与解析语义

首轮执行范围沿用静态计划的节点、非嵌套 select、DOMAIN、DOMAIN-SUFFIX、字面 CIDR no-resolve 和唯一末尾 MATCH。原 YAML、完整合并数据和组选择分别保留，未支持字段可供私有下载。只有已证明语义可执行的子集才可检查与应用。

检查须验证每个被引用上游的身份、TLS/SNI 配置引用和全部地址答案。实际 TLS 握手及客户端通路由独立诊断和验收记录证明。检查结果须绑定自机地址快照、节点 revision 和工作区 revision。不能把一个上游的结果用于另一上游，也不能把旧配置中的解析结果借给新草稿。保护解析的出口必须显式确定并进入计划指纹，解析故障阻止应用和流量绕行。

no-resolve 不能通过对所有请求提前解析来模拟。域名、字面地址、规则顺序及保护地址检查须共同验证。编译可以增加保护动作，但不能让原本不匹配的前序规则因新增解析而命中。具体动作序列须经固定 Mihomo 与受管 sing-box 的实际对照确认后冻结。

## 保存与能力门槛

应用计划与原文含有节点凭据，存入服务用户独占的私有材料。普通工作区、任务和状态响应只提供固定版本、摘要、计数和状态。未知字段、原文、材料路径、上游凭据及原始冲突路径不得进入普通响应或日志。

拟在 ProxyStore 增加单调的第三版能力门槛，并增加能够绑定 YAML 私有材料的不可变 revision 格式。旧版一、二状态沿原规则读取。第一次保存新计划之前完成能力门槛持久化，失败时保留可恢复状态。旧 reader、代码回退、安装升级、备份及恢复消费者都须识别新门槛。需要同步 `release_tools` 的活动策略保护、恢复能力下限、发布兼容检查、`proxy_recovery`、核心升级冷检及固定 CONTROL 依赖闭包。恢复只读取严格的规范 JSON 清单和已验字节，Root 不解析原 YAML。

检查票据和运行指纹须绑定所选核心制品、编译器版本及全部上游解析快照。应用时重新核对票据和快照，不能把检查后重新解析得到的不同地址视为原确认结果。

规范计划记录独立于 YAML 解析器。记录同时保存原规则目标、解析后的目标与显式分组选择，读取时逐条核对。原文件以独立私有材料保存，计划只引用其摘要。规范字节决定记录身份，调用方取得的可变副本不改变原记录。

上下文须绑定计划摘要、显式组选择、保护解析出口、每个命名上游的规范身份及解析快照、受影响入站清单、节点源指纹、运行指纹和最终配置 revision。上下文中的明文身份与解析数据留在私有存储中。

## 检查、应用与恢复

复用 CoreManager 的全局操作锁和另一核心检查，复用 ProxyApplyCoordinator 的检查、持久事务、配置预检、激活、实际回读及失败恢复顺序。应用请求必须提供检查过的工作区 revision、节点源指纹、运行指纹、计划摘要及幂等标识。

首轮应用要求目标 sing-box 已在运行。已停止时仍可检查和下载计划，运行应用须由用户明确启动后重新检查。提交前再次核对启停意图，拒绝把检查后的停止操作解释为启动许可。

检查成功后若节点、开关、组选择、来源材料、上游地址快照或运行意图变化，应用拒绝并要求重新检查。相同幂等标识只能返回原事务结果，不能在新草稿上重放。

本机代理的监听预检取决于本机开关和实际本地入口，不能以计划是否引用上游为条件。全为 DIRECT 或 REJECT 的计划也须核对监听占用和归属。

停机前保留旧活动配置、原启停意图及私有备份。成功须同时证明完整配置已运行且事务已提交。启动失败恢复原活动配置及原启停意图。中断恢复消费持久记录，未知或无法确认的状态保持受阻。原数据与节点凭据继续保留。

## 私有存储候选

ProxyStore 的内部保存接口已接入规范计划和三份源材料。草稿使用第二版不可变 revision，state 的第三版门槛先于新材料写入，并在私有 secrets 目录保留独立 capability 记录。清空或丢弃草稿继续保留门槛。保存中断时旧草稿保持，遗留材料经验证后可进入私有备份。

新存储格式已进入候选。管理员保存与清空草稿接口已进入候选，分别要求强 If-Match 与同源请求。保存前在受限 worker 中检查当前冲突指纹、组选择和规范计划，返回工作区摘要。面板保存控件和第三版应用上下文尚待接入，旧单上游应用路径遇到 YAML 草稿会拒绝。经典活动版本仍由原事务读取。固定 CONTROL 增加规范记录读取器，历史 PRE_DNS、DNS、CORE 依赖组保持其原集合，新增 YAML 组单独核验刷新。

## 当前迭代与验收

下一迭代先完成新不可变材料与能力门槛的读写、并发和恢复契约，然后接入同一事务下的多上游检查和编译，再接面板检查与显式应用。每步都要包含对应旧 reader 及备份恢复验证。

Actions 验收需要真实规则对照、重叠规则首条命中、多个明确出口、拒绝及出口故障、DNS 与 no-resolve 交互、自环地址拒绝、旧入站与另一核心保持、并发提交、幂等重放、旧格式迁移、切换失败回退和中断恢复。安装验收绑定同提交构建及同一轮收据。浏览器验收按用户明确授权执行。
