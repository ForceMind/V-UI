# 专用订阅的节点实例绑定

## 2026-10-22 独立开发候选，尚未发布或部署

基线为 `fc9796523c0ed30f47b0fe14ba4b319bbdda74d7`。本候选修复专用订阅只保存整数入站 ID 的授权缺陷：SQLite 删除最高 ID 后可能自然复用该 ID，旧令牌不应因此导出另一个新节点的凭据。无需禁止 SQLite 复用 ID，也不改变客户端协议或运行配置。

本次仅在隔离的临时数据库开发与验证；没有迁移实际用户数据库，没有发布、部署、改变固定核心、`VERSION`、权限或 Tailscale / 受限 UDP D2 范围。独立安全复审、准确候选和主线 CI、实际浏览器与既有发行门槛须分别完成，不能继承基线资格。

## 有意的兼容性变化：升级前的订阅必须重新创建

旧授权只有整数 ID，不能证明授权时选中的节点就是目前占用这个 ID 的实例。即使当前 UUID、端口或标签看似合理，也不能补出缺失的历史证据。迁移只为旧节点分配新的实例身份，绝不根据当前 ID 为旧授权自动补绑定。

因此，旧专用订阅升级后失效，必须由管理员重新选择经过确认的当前节点，明确创建新订阅，再更新客户端 URL。不能点击“轮换”来修复旧授权。旧记录保留可撤销，不删除历史，不把失效误称为密码变更。

工作区列表分别显示“旧授权缺少节点身份，请重新选择节点并创建订阅”或“节点已删除、重建或身份异常，请重新创建订阅”，并禁用这些记录的轮换按钮。管理员 API 的轮换请求返回 409 和重新创建指引；公开令牌端点只返回通用 404 / 409，不披露节点身份、凭据或内部损坏细节。

## 身份和授权契约

- `inbounds.instance_id` 是服务端生成的随机 128-bit 身份，保存为 32 位小写 hex。每次创建新行生成新身份；普通编辑保留身份。同实例的合法 UUID / 密码 / 端口 / 标签修改不要求重新授权，其他无关的有效绑定不受影响。
- 现代、旧 Xray / sing-box API 以及创建/编辑服务拒绝顶层 `instance_id` 和 `inbound_bindings` 输入。复制原始配置来创建节点仍分配新身份，不接受调用方提供的旧身份；嵌套的核心配置字段不能覆盖数据库身份。
- `subscription_grants.inbound_bindings` 保存准确的整数 ID → 实例身份集合。读取与轮换都要求完整集合精确匹配，不接受少一个节点、多一个节点、错误类型、重复 ID、越界 ID、重复 JSON 键或缺失/畸形身份。所选身份若在另一当前行重复，也拒绝该授权。
- 身份或绑定失败时，三种格式全部失败，不导出剩余子集、不回退 DIRECT。轮换先验证绑定，再生成令牌和修改状态；失败不改旧 token hash、凭据戳、到期时间或撤销状态。原节点只是停用时可重新启用；只有确认仍是同一实例后才可轮换。
- 创建与轮换使用 SQLite `BEGIN IMMEDIATE`；公开读取和管理员列表使用显式读事务，确保授权和当前节点来自一个数据库快照。并发删除/重建不会将一次读取中的旧授权接到新节点。
- 新身份/绑定不进入普通节点摘要、特权编辑器返回、订阅列表或客户端导出，也不加入运行配置、路由 source fingerprint 或代理 runtime 身份。它不是协议 UUID、密码、可公开 token，也不扩大协议资格。

## 迁移与损坏边界

`init_db` 在原 operation / data-owner 锁内，以一个 `BEGIN IMMEDIATE` 事务执行预检查、`create_all` 和迁移。原 per-inbound policy schema 与 `RECOVERY_REQUIRED` 防线不变，也不借用代理 schema 版本表达订阅能力。

独立 SQLite 表 `subscription_identity_schema` 只允许一个整数版本 `1`：

1. 已有该标记时，缺失 `inbounds` / `subscription_grants` 表或任一新身份字段、未知/空/重复/畸形标记都在建表前拒绝启动，不把损坏当前库当作旧库修复。
2. 无标记且确实缺少实例字段时，允许初始化旧节点身份；但若现有 grant 绑定字段已有非空内容，拒绝自动生成身份。旧 grant 缺少绑定字段时仅新增 nullable 字段，保持未绑定。
3. 已存在的身份字段即使值为 NULL、空、未知格式或重复，也不重新生成。现有节点须恢复经过验证的完整数据库，或明确重建节点并重新授权；读取、列表、轮换都不能“修复”为当前 ID。
4. 标记与两列一同提交。迁移异常或提交前进程退出由 SQLite 事务回滚，重启后可以重新执行完整迁移；不删除或重建旧数据库掩盖故障。

无标记且两列均不存在，与真实旧库在本地不可区分。这条迁移规则不是防恶意数据库篡改的证明，也不承诺检测所有人为删除元数据的组合；此时旧授权仍无可证明绑定，拒绝使用。拥有数据库写权限的人可重写身份、绑定和 token hash，本修复不提供针对该权限的密码学完整性保护。

## 备份、恢复与旧程序回退

现有 SQLite 全量备份会保存身份、绑定及独立版本标记。完整一致恢复保留这些记录；但是普通 `release_tools.restore` 和专用 `proxy_recovery` 原有的撤销规则保持：删除恢复的管理员会话，撤销全部恢复的订阅访问。保留记录不等于让旧 URL 恢复可用。管理员明确轮换时，仍须先证明绑定的全部原实例完整一致；旧未绑定授权只能重新创建。

混合/部分恢复不能自动重绑定：新 grant 搭配另一节点身份会失效；带标记却缺列/缺表拒绝启动；旧完整库迁移后旧 grant 保持无绑定。恢复仍服从原完整数据目录交换、停止服务、校验摘要、`RESTORE_PENDING.json`、代理策略和恢复日志边界，不自动重启或放宽原失败关闭约束。

重要：旧二进制不读取这些新增字段，仍可能只按整数 ID 授权。本候选的独立 SQLite 标记不让旧 reader 自动拒绝，既有发行 activation fence 也只保护代理路由能力，不能声称已提供订阅能力的旧版本回退保护。不得将身份迁移后的库交给旧二进制继续提供在线订阅；安全回退须保持服务停机和访问隔离，另行审查完整备份、版本及所有旧链接的处理，不能以清空/改名数据库或直接降级绕过此限制。
