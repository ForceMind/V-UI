# D2 固定官方核心的 IPv4 UDP 双跳实验

基线为 `dd4c22eb8a4b98f88bba436cadbebdb49f5ce7c4`。设备端使用官方 Mihomo 1.19.32，国内及海外角色使用官方 sing-box 1.14.2。实验核对源码提交、固定下载包和实际可执行文件的 SHA-256。所有 listener、应用目标与禁区对照均为临时 Linux runner 内的 IPv4 回环高端口。两跳都使用 VLESS/TCP、XUDP 和各自的临时 CA 验证 TLS。

用独立草稿 PR 触发 **D2 stock-core UDP experiment**。复跑同一提交可在 Actions 选择 **Re-run all jobs**。每轮制品名包含准确提交及 attempt，`report.json` 保存每场景的状态、目标账本、回包地址和端口、载荷长度及 SHA-256。逐场景的脱敏核心日志独立保存。run 失败时仍上传证据。

- 非连接式小包对照和连接式门槛分别检查 1、1200 字节。应用目标端口与海外 VLESS 监听端口必须不同。连接式路径按方向检查 8192、32768、60000 字节，另一方向用 1 字节对照。受控接收器采用足以容纳整个数据报的缓冲区。
- 每场景先直接核实应用目标和禁区对照可达。正常转发的目标账本只接受来自海外角色专用回环源地址的精确载荷。拒绝场景分别验证同一关联改投禁区、两跳的错误 UUID、CA 和 SNI，以及海外停机。拒绝需要新鲜核心原因、观察窗内零误送达和无 DIRECT。
- 同一应用关联先完成 60000 字节往返，再经历完整 6 秒空闲窗口。独立关联在窗口内维持流量，观察原海外 UDP socket 释放。随后通过原 SOCKS 控制 socket、UDP 源 socket 和 relay tuple 请求新的 32768 字节往返。前序门槛失败时，后续场景标记为未执行。
- 受控共享 mux 写阻塞需要独立的阻塞与回收证据，报告单列其状态。历史 mux 背压结果见 [D2 原记录](https://github.com/ForceMind/V-UI/pull/48)。

本轮有界场景失败或未执行时，判定为受阻。共享 mux 写阻塞单独记录为产品资格的前置证据。保留本轮实际结果及旧实验失败。测试配置和假凭据只存在于临时目录。产品 UDP 中转、公开导出及部署范围见 [ROADMAP](../ROADMAP.md#后续)。
