# 运维、升级与恢复

本页适用于 v0.4.22 受管安装，默认根目录 `/var/lib/v-ui`。先使用全局 `v-ui` 菜单，只有需要处理菜单之外的故障时才按后文选择活动运行时。不要直接改数据库、删除恢复日志或替换活动版本文件。

## 终端运维菜单

在交互终端执行：

```sh
sudo v-ui
```

打开菜单不下载套件。全局受管菜单使用固定系统解释器和受信控制组件；完整系统操作限 systemd，OpenRC 当前仅支持状态查询与本地候选准备。

| 选项 | 操作 |
| --- | --- |
| `1` | 查看受管服务状态 |
| `2` / `3` / `4` | 启动 / 停止 / 按当前运行拓扑重启 |
| `5` / `6` | 停机创建私有备份 / 校验并停机恢复备份 |
| `7` | 选择已准备版本，用于升级或代码回退，先备份 |
| `8` | 准备可信本地候选，不激活 |
| `9` | 完成中断还原的恢复 |
| `10` | 只读网络与防火墙诊断 |
| `11` | 明确确认后精确放行受支持的本机端口 |
| `12` | 在线升级官方稳定版，选择并确认后才下载 |
| `13` | 创建、列举或撤销维护授权 |
| `h` / `0` | 帮助 / 退出 |

服务管理器状态不等于 HTTPS、证书或节点转发健康。操作失败后菜单不会自动恢复启动，应先看结果和日志，再按原运行拓扑恢复；不要假定再次启动就已修复。所有写操作需等前一次任务明确完成，忙碌时不重复提交。

### 包内非 root 菜单

旧式或自定义安装还保留由安装目录所有者运行的包内菜单，见后文运行时选择。其 `1` 为服务状态、`2` 为活动版本信息、`3` 为完整校验、`4` 为准备本地候选，`h` 帮助、`0` 退出。它不执行全局菜单的启停、备份恢复或激活操作：

```sh
sudo -u v-ui "$PY" -B "$APP/scripts/deploy.py" --root "$ROOT" menu
```

目录须已存在、无符号链接、归运行用户所有且权限为 `0700`，不能以 root 运行。候选准备会执行可信包内代码并占用 CPU、内存和磁盘，不提供沙箱；只使用已接受来源的包和独立核验的摘要。完整控制、锁与候选准备边界见[受管运维](MANAGED_OPERATIONS.md)。

## 在线升级与版本管理

1. 保留离机备份，核对当前版本、平台和安装来源。
2. 选择菜单 **12**，确认目标后开始。只获取官方受信稳定版及本机架构套件，已经相同或更高版本时不降级。
3. 等待任务完成，核对活动版本、HTTPS 健康和节点实际应用结果，再用客户端验证连接。

升级校验候选、停止自己的受管服务、创建私有备份、激活并进行 HTTPS 检查。失败会尝试恢复原配置和代码选择，**结果以任务报告及实际状态为准**；无法确认时保留备份和诊断，通过终端恢复。已有账号、节点、订阅、证书与代理设置沿用，不删除或重建数据来处理升级问题。

旧菜单没有 12 时，使用[短安装入口](INSTALLATION.md#1-一行安装)选择 `2` 升级。手工套件升级先按[本地完整套件](INSTALLATION.md#3-本地完整套件)校验并准备 `run_vui_local_installer`，核对原安装参数后使用 `--upgrade`；不要把 CPU、libc 或 service manager 迁移当作普通升级。

本地候选准备和激活是两个步骤，准备成功不代表版本已切换。菜单 **7** 的代码回退与菜单 **6** 的数据恢复也不同；变更过数据库或配置时，不能只切换程序目录。保留原版本运行时和备份，不手工清理未知候选。固定代理核心随正式套件验证，不提供任意独立在线换核流程。

HY2 / TUIC 的 UDP 安装声明不持久化；需要升级时检查这些规则，须重新传入每个 `--node-udp-port`，并人工核对端口所有权。升级不会重新 bind 正在运行的节点，也不证明端口空闲。

## 远程维护

面板“远程维护与升级”或终端菜单 **13** 可创建限时授权。默认**只读、30 分钟**，最长 **180 天**；终端有效期可输入分钟数，或 `180天` / `180d`。按需要选择只读、日常或完整维护，完整维护包含删除与备份恢复，可能永久改变业务数据。

维护链接仅显示一次，首次兑换后原链接失效；会话沿用原截止时间，兑换不重新计时。旧授权不会自动延长。只交给可信维护者，可随时列举和撤销；管理员改密或停用也会使授权失效，恢复备份会清除旧维护授权和会话。

撤销阻止后续请求，已受理的任务继续安全完成或失败，不强杀正在升级的任务。独立 `v-ui-maintenance.service` 可在面板重启期间继续执行已受理任务；面板可查看状态和脱敏日志。面板或网络完全不可达时，仍需要服务器终端。维护不开放任意 shell、文件路径、下载 URL 或 SSH/云防火墙修改，详细权限见[维护契约](REMOTE_MAINTENANCE_CONTRACT.md)。

## 备份与恢复

推荐使用菜单 **5** 创建备份，并记录路径与 SHA-256，再将副本保存在受保护的离机位置。备份包含数据库、节点秘密、证书私钥和 CA 账号，**未加密**，不得放入公开下载目录、Issue 或源码仓库。保留权限、所有权和对应版本信息。

恢复用菜单 **6**，只选择可信备份并核对摘要。恢复会撤销旧管理会话、订阅令牌及维护授权，恢复后需要重新登录、授权并重新交付订阅。不要把“代码回退”当成“数据恢复”。

出现 `RESTORE_PENDING.json` 或中断恢复提示时，保持停机，使用菜单 **9** 完成恢复，再核对结果。不要删除标记文件绕过检查。备份目标文件系统需支持硬链接；归档发布后目录同步失败可能留下完整文件，仍应按失败报告核对，不覆盖或删除它来掩盖结果。

### 手工备份与恢复

仅在已确认下节活动运行时、具备终端恢复能力且停止所有相关写入者时使用。systemd 停机备份示例：

```sh
sudo systemctl stop v-ui-http01.socket
sudo systemctl stop v-ui-http01.service v-ui.service
sudo -u v-ui "$PY" -B "$APP/scripts/deploy.py" --root "$ROOT" backup "$ROOT/manual-backup.zip"
```

目标不能覆盖已有备份。备份完成后按原运行拓扑恢复服务，不直接假设此前所有服务都在运行。手工恢复调用为：

```sh
sudo -u v-ui "$PY" -B "$APP/scripts/deploy.py" --root "$ROOT" restore '<可信备份的绝对路径>' --sha256 '<已核验的SHA-256>'
# 仅当提示存在中断恢复时执行：
sudo -u v-ui "$PY" -B "$APP/scripts/deploy.py" --root "$ROOT" recover-restore
```

## 服务状态与日志

systemd：

```sh
sudo systemctl status v-ui.service v-ui-http01.socket v-ui-http01.service
sudo journalctl -u v-ui.service -n 100 --no-pager
```

HTTP-01 socket 为 `active/listening`、responder 为 `inactive` 可以是正常按需响应。状态快照不能代替 HTTPS 和节点检查。需要重启时优先菜单 **4** 保持运行拓扑。

OpenRC：

```sh
sudo rc-service v-ui status
sudo rc-service v-ui-http01 status
sudo rc-service v-ui restart
```

## 选择活动运行时

高级手工操作先从安装器输出或 root 控制的 `/etc/v-ui/service.json` 取得已知安装版本：

```sh
ROOT=/var/lib/v-ui
ID='<填写本次安装输出的 release_id>'
case "$ID" in ''|*[!A-Za-z0-9._-]*) printf '%s\n' '请填写有效 release_id'; exit 1;; esac
case "$ID" in [A-Za-z0-9]*) ;; *) exit 1;; esac
test "${#ID}" -le 101 || exit 1
PY="$ROOT/releases/$ID/runtime/python/bin/python3"
APP="$ROOT/releases/$ID/payload"
```

安装记录可能不是当前活动版本。先用该已知版本打开包内菜单，选 **2** 核对活动版本，再更新 `ID`、`PY` 和 `APP`。不要用旧 `venv/bin/python`，不要 source 配置，也不要以 root 执行服务用户拥有的 `$PY`。

管理员忘记密码时，停止面板后，以已确认的活动运行时执行：

```sh
sudo -u v-ui "$PY" -B "$APP/scripts/deploy.py" --root "$ROOT" admin set-password my_admin
```

把 `my_admin` 换成实际管理员名，密码交互输入，不放入 shell 历史。入口使用操作锁和面板锁，不同时运行其他写库脚本。

## 网络与端口变更

先用菜单 **10** 诊断，再在确有需要时用 **11** 精确放行。仅修改已安全识别且启用的 UFW/firewalld 并回读，不自动启用防火墙、猜 zone 或改 SSH、云安全组、自定义规则；也不自动删除可能被其他服务复用的旧规则。修改节点或面板端口后，同步核对实际监听、主机规则、云入口与客户端地址，TCP 和 UDP 分别检查。

遇到失败先按[故障排查](TROUBLESHOOTING.md)保留必要诊断，保持 TLS 验证开启。历史运维实现和验收范围见[历史索引](history/README.md)；当前版本**浏览器未验证**。
