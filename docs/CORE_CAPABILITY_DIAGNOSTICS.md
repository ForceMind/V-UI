# 核心版本与运行身份诊断

这是 [Issue 175](https://github.com/ForceMind/V-UI/issues/175) 中 W1 的第一块实现：让代理页面区分兼容基线、当前选择和经过核对的运行版本。完整的安装环境、端口、防火墙及公网诊断仍按后续任务分别验收。

## 用户看到的状态

在“中转与服务器代理”的高级工具中，展开“当前状态 → 核心版本与兼容范围”。“刷新服务器状态”同时更新版本观察；网络读取失败时清除旧的已核对显示，草稿与活动配置的刷新仍可独立完成。

| 字段 | 含义 |
| --- | --- |
| 兼容基线 | 本应用记录的固定核心资格基线，不随某次组件选择改变。 |
| 当前选择 | 当前面板启动时选用的版本；来源为随应用提供或独立受管组件。旧随包路径只能给出预期版本。 |
| 已核对运行版本 | 活跃进程所持可执行文件的描述符、字节摘要和生成身份已核对，且与当前选择一致。 |
| 当前未运行 | 已存在的运行时观察到进程停止；不代表用户要求启用。 |
| 尚未取得运行记录 | 面板尚未创建该核心的运行时，不推断机器上不存在其他进程。 |
| 版本身份未核实 | 观察到进程，但没有完整描述符证据或核对未通过。 |
| 核心操作进行中 | 正在执行其他核心操作，本次读取不等待操作完成；稍后刷新。 |
| 与当前选择不一致 | 活跃生成有有效描述符证据，但与当前选择不同。即便版本号相同，也不能显示已匹配。 |

该观察不证明协议、导出格式、公网端口、TLS、代理认证或客户端连接成功。已有节点继续使用真实导出器计算资格；协议编辑目录不能直接当作已验证组合清单。应用、导出和恢复继续执行原有服务端守卫。

## 接口兼容与权限

`GET /api/proxy/capabilities` 保留 `schema_version: 1`、原功能开关和 `core_version`。`core_version_semantics: qualification_baseline` 明确原版本字段含义；新增 `cores`，只包含固定的 `xray`、`sing-box` 两项。

每项只包含 `qualification_baseline`、`selected_version`、`selection_source`、`running`、`running_version`、`identity_state`、`matches_selected`。缺少证据的运行版本和匹配结果为 `null`，不能拿选定版本填充。`running` 为 `null` 时表示尚未观察到确定结果。

接口沿用管理员鉴权和既有 `diagnose` 维护权限，不扩大为 `core_read`。组件 ID、来源提交、清单、摘要、文件路径、PID、候选和回退详情均不经此接口公开。独立组件选择仍使用现有受限维护入口。

## 只读约束

观察只读取已存在运行时和冻结的启动选择，不调用可能编译、停止或恢复配置的综合状态路径。取得管理器和运行时锁时不等待；不创建运行时，不初始化存储，不访问网络，不清理退出进程，不调用 Root 服务。活跃生成复用既有可执行 FD 验证器。

该结果是瞬时诊断，没有执行或发布授权含义。`apply_available` 等原字段继续表示产品是否开放相应操作，不因一次未运行、繁忙或未验证观察而改变。

## 验证范围

相关回归包括 `test_core_capabilities.py`、`test_proxy_api.py`、`test_maintenance_auth.py`、`test_core_runtime_artifact.py`、`test_core_runtime_confirmation.py` 和 `proxy_yaml_sync_dom.js`。测试使用私有临时文件、假进程、合成 ASGI 与 DOM；真实浏览器和真实部署需要独立证据。

首次维护权限用例错误地进入完整 ASGI lifespan，触发数据目录安全检查并失败；已改为与本文件其他授权测试一致的无 lifespan 请求夹具，保留生产检查与断言。
