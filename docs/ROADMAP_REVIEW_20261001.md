# V-UI 版本迭代计划

## 复核结论与当前版本

**2026-10-01 复核：路线可按小版本执行，但此前的验收条件并不完整。** 本文补齐边界，不把既有草稿代码或单元测试通过当作可发布证据。

当前只推进 **v0.3.0-alpha.2：管理员登录与管理鉴权**。不在本轮实现独立订阅令牌、改协议或修改 ToClash 规则。完成本轮验证/交付后停止，不自动进入下一版本。

基线为 alpha.1 的 `1963969b781cd6d8b84db2e1ff3da5f0da5499e0`（[PR #2](https://github.com/ForceMind/V-UI/pull/2)，[CI run 57](https://github.com/ForceMind/V-UI/actions/runs/36837822466) 已成功）。原 PR #1 保留为冻结的集成草稿。alpha.2 使用叠加在 alpha.1 上的独立分支/PR，不擅自合并 PR #1、PR #2 或 master。后续集成前先处理前置 PR；不把未合并的依赖藏起来。

| --- | --- | --- | --- |

| **alpha.2** | **管理员认证边界** | 无默认密码和 mock token；登录/改密/退出闭环；所有管理、旧别名和暂存订阅接口鉴权；CSRF、过期/撤销、限流与旧数据保留回归 | **本轮** |

| alpha.4 | 核心配置安全应用 | 固定核心版本校验候选配置后才替换；失败保留原配置与运行进程；数据库期望态/实际生效态明确；并发修改、异常退出、重启恢复和回滚回归 | 未开工 |

| rc.2 | 发布与部署门槛 | 对选定部署方式验证依赖/二进制来源与固定版本、权限、HTTPS、前端依赖、安全接口、数据备份/恢复、安装更新/回滚；明确架构和未支持项 | 未开工 |

正式版本号为 `v0.3.0-<阶段>`；表内省略前缀。候选版本不是正式 Release，RC 通过也不自动部署。新增 RC.2 是补回此前遗漏的发布门槛，不是提前开发部署功能。

## 本轮 alpha.2 的范围

- 单管理员模型，不建设多租户、角色权限、支付或机场后台。
- 复用 SQLite `users`；新增会话与登录限流表。无默认账号/密码，无公开注册口。
- 本机交互式 CLI 创建或重置账号，不通过命令参数传密码。未知旧哈希不自动获得登录权限，走显式本地重置。
- Argon2id 保存密码；随机会话令牌只以摘要入库；HttpOnly/SameSite cookie；固定过期时间，重新登录换令牌，退出/改密/重置可撤销。
- 默认保护所有 `/api/*` 和 OpenAPI；仅登录 POST 匿名开放。旧 `/api/xray/*`、`/api/singbox/*`、分享和所有订阅格式无例外。
- 状态变更要求精确 Origin 和自定义请求头，移除通配 CORS；新表单错误不回显密码；登录请求实际字节有上限；限流跨进程请求持久保存。
- 未配置公开来源时仅允许回环访问；公开来源必须 HTTPS。应用默认监听回环，不信任客户端提供的转发地址头。
- 登录/账户页使用本地资源；旧面板“设置”入口进入账户页。订阅客户端在 alpha.3 前不能匿名拉取，这是有意的安全边界，不回退为公开凭据。
- 上传网站与面板共用来源会扩大认证风险。本轮只**暂时隔离站点访问和上传/列表接口**，保留已有文件，不开发站点托管安全方案。

不改 Xray/sing-box 配置字段、客户端导出器、ToClash 规则、证书申请、核心版本管理或现有入站编辑功能。

## ToClash 必须合入的能力和边界

ToClash 已在 alpha.5 / alpha.6 的正式队列，不是候选项。PR #1 中已有的 Python 移植和 UI 只作为待验收实现；不能把“代码已有”写成新版本完成。

### alpha.5：配置引擎

1. 固定 ToClash 的提交（当前参考 v0.3.8），保留来源/许可与适用 NOTICE。运行时无需 Node 常驻进程，也不把节点凭据发往在线转换服务；参考实现和差异验证可只在开发/CI 使用 Node。
2. 基准覆盖常规/默认直连模式、服务预设、用户直连/代理、局域网、可选 CGNAT、父子域冲突、内网 DNS、fake-IP 排除、独立节点 DNS 及保留名/重名。
3. 比较解析后的 YAML **语义及有序规则/DNS 项**，不是只比较文本或在两侧复用同一套可能错误的实现。
4. `FORCE_PROXY` 后相邻 `REJECT` 针对继续匹配的路径；不能描述成代理连接失败的通用回调，更不能保证未进入 Mihomo 的流量不直连。
5. 服务静态域名表不代表完整流量覆盖；沿用原四项默认选择，其他按需，不未经验证把共享 CDN 的整个父域强制代理。
6. 单独验证节点连接参数与规则。导出不得泄露私钥/服务端证书路径；不得静默丢失 TLS、SNI、传输参数、认证字段或未知选项。空节点/不支持组合应明确失败或使用显式选择的仅节点模式，不能悄悄变为全部 DIRECT。
7. 最小闭环先限定已验证的 VLESS/TLS 组合；为其他协议逐项记录“未验证/不支持/已验证”的版本矩阵，后续独立迭代扩展。**不承诺所有服务端协议都能无损导出成所有客户端格式。**
8. 节点公开连接地址独立配置，不无条件沿用面板 Host/CDN 域名。主机/IP/IPv6、端口和编码有测试；订阅地址与节点地址不是同一概念。

完整 Mihomo 输出包括 `proxies`、`proxy-groups`、`dns` 和 `rules`。Base64/URI 不承载整套分流；sing-box 的 DNS/规则格式不同，其完整分流转换不计入首轮 ToClash 合并验收，不能只改字段名冒充支持。

### alpha.6：面板直接使用

只接已验证引擎，收口现有网络模式、服务开关、始终直连/代理、CGNAT、内网域名/DNS 表单。保存、草稿与预览必须有清楚状态；非法设置不能偷偷写成默认值。相同订阅 URL 返回最新已保存设置，但客户端要手动或按其计划刷新，不能声称保存后所有设备即时生效。

目标使用链路：**V-UI 设置节点/分流 → 受保护的订阅地址 → Mihomo 客户端刷新配置**，无需再手动复制到 ToClash。

不在此版搬运整个 ToClash UI、不增加任意 YAML 导入/合并、不做跨仓库自动更新、不增加第二套规则实现。

## 跨版本必须遵守的验收规则

- 历史 Xray `users/method` 转换及 REALITY 兼容提示仍需官方资料和固定版本真实核心复核；原自定义测试的期望值不是外部兼容性证据。发现不成立时在对应核心/导出版本修复，不在本轮顺手改协议。
- `core -test/check` 只证明配置加载，不能代替连通性。alpha.4 就开始固定版本检查，不等 rc.1 才发现基础字段错误。
- 新增测试应包括失败路径；失败、空结果、超时不得返回“已应用/已导出”假成功。
- 数据改变前有备份/迁移/恢复说明；不得清空旧入站或换目录当成升级。一次只运行明确受支持的部署模式。
- 本轮登录页浏览器检查不等于旧主面板全部控件已验证；前端远程未固定依赖仍是 rc.2 发布阻塞。
- 鉴权是第一层保护，不是完整安全审计。站点托管、系统/防火墙权限、前端供应链、核心下载/更新及部署配置仍需各自验收。
- master、Release 和 VPS 只有在明确要求及验收后才变更；未取得部署证据，不写“已部署”。

## 后续候选池（不与当前版本并行）

现有节点可视化编辑/参数回填 → 逐项扩展已验证协议/导出矩阵 → 证书导入管理 → ACME 申请 → ACME 续期 → 核心升级/回滚 → 可选既有 YAML 导入/合并。每次只选一项，开工前再定唯一验收目标；不按清单连续自动开发。

## 交付与回滚

每轮报告目标、变更文件、准确提交、CI/本地/浏览器的实际结果、未测项目及下一项。本轮 CI 以该 PR 最新提交为准；queued/running 不算通过。不得沿用 alpha.1 的成功记录给 alpha.2 背书。

alpha.2 会新增认证表并用 Argon2id 保存通过本机创建/重置的账号，不删除入站数据。回滚应先停服务并保持防火墙/回环隔离，再恢复备份；**不能把回退到没有鉴权的 alpha.1 当成安全的在线回滚**。
