# Docker 与 NixOS 部署验收契约

P7 首批交付分别限定 Docker 和 NixOS。当前公开 v0.4.27 的安装支持见[兼容矩阵](COMPATIBILITY.md)。本页定义开发交付与通过条件。Docker 和 NixOS 均未做整机验收或发布。

## Docker 首批

仓库的 [Dockerfile](../Dockerfile) 读取第三方 latest 并下载未固定摘要的核心，现有 [Compose](../docker-compose.yml) 使用 host networking 且覆盖镜像内的前端。它们只作为历史开发材料。正式方案从准确提交产生同源镜像，首个验证目标限定 Linux x86_64 GNU，ARM64 GNU 另跑原生验证。原有四个 Linux 包的通过记录只作为输入来源证据。

| 场景 | 通过条件 |
| --- | --- |
| 来源 | 镜像基座、应用和固定核心的来源与摘要可核对。镜像标签、digest、应用提交与两核心身份有同一份构建收据。摘要错、目标错或材料不全则拒绝构建。 |
| 启动 | 服务以普通用户启动，明确挂载一份独占的私有持久目录。只公布选择的管理与节点端口，保留 TLS、认证及 Host/Origin 限制。使用自备可信证书，HTTPS 回读通过后才交付管理员入口。 |
| 权限与网络 | 首批使用隔离桥接网络，不使用 host networking、Docker socket、privileged 或自动改防火墙。未获资格的运行模式有显式拒绝。应用、节点 TCP 和宿主机入口分别验证，阻止意外监听或退回直连。 |
| 数据和升级 | 停止前核对持久目录和唯一写入者。升级保留账号、数据库、既有节点、订阅和绑定；容器删除或重建后同一私有卷仍可恢复。错误配置、卷不可写、第二写入者、不同主机绑定和启动失败保留原数据并阻止上线。 |
| 回退和恢复 | 固定旧镜像及私有备份先于升级可读。实测失败换版或中断后按可读版本与证据恢复；旧 reader 无法读取新数据时执行备份恢复纪律，验证旧凭据撤销、原服务意图和实际 TCP。 |

交付物为固定输入的构建与最小 Compose，以及空白 Linux runner 上的实际镜像、真实客户端与恢复证据。镜像保留许可证，数据、证书与用户配置由实例私有提供。宿主机自动更新、ACME 自动签发和多实例共享卷另行定范围。

## NixOS 首批

首个验证目标限定 NixOS x86_64 GNU 上的单实例声明式服务。独立验证其包、服务和数据生命周期。通用安装器不用于该路线。

| 场景 | 通过条件 |
| --- | --- |
| 来源与服务 | 以固定 Nix 输入构建应用、运行时与核心，记录应用提交和产物身份。Nix store 仅包含不可变程序材料，服务以固定普通用户运行，复用既有核心校验。 |
| 状态与证书 | 仅为该实例配置可写私有状态目录，数据锁与文件所有权受验。证书、密钥和管理员材料从运行期私有路径加载；生成的声明、派生物与日志无秘密。TLS 故障拒绝启动，正确配置回读原域名和应用鉴权。 |
| 网络边界 | 面板与节点的地址和端口显式声明。负向验证未配置端口和网络边界，不由模块改动无关规则。通过现有受支持核心验证实际 TCP 正负向。 |
| 切换与恢复 | 在干净模拟主机用两份固定系统代次测试初装、配置重载、重启、更版失败与回退。系统代次回退不覆盖 SQLite；需回退数据时使用明确快照、恢复日志与撤销规则。保留原服务启动意图。 |
| 可复核证据 | 提交、输入锁文件、产物身份、系统代次、测试场景和结果可追溯。真实流量和启动失败恢复均执行，跳过项保留。 |

交付物为独立的声明式模块、固定输入及虚拟机验收。包升级随声明执行，原在线升级能力先按明确边界拒绝。Docker 验收结果不授予该环境资格。

## 当前恢复条件

Docker 需固定镜像来源并在 Linux runner 接入容器验收，NixOS 需固定系统输入与独立虚拟机验收。当前工作树未构建镜像、系统代次或运行测试。P7 后续实现和各平台验收依据本页逐项记录。生产安装、公开分发和新增资源各自沿用现有授权。
